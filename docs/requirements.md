# 产品需求与验收基线

状态：当前产品需求基线。已实现两段整屏首页与本地主回忆、相册和全部影像浏览、媒体查看器、首页背景音乐，以及海边沙滩/旷野草原两套主题与偏好记忆。本文只记录当前产品行为；实施后同步实际结果。

## 项目目标

网站中文名称为“王乐悠”，完整显示名称为“王乐悠 · 成长相册”。

本项目是记录孩子成长与家庭生活的纯前端影像网站，通过 GitHub 仓库管理源码、照片、视频和相册配置，构建后可部署到 GitHub Pages 公开访问。

核心目标：
- 浏览相册与生活照片，播放全屏照片幻灯片、生活视频和背景音乐。
- 兼容 PC 和移动端浏览器，为未来 App WebView 套壳预留适配边界。
- 界面整洁、大气、阳光、温暖，以家庭影像内容为中心。
- 工程按业务能力划分模块，职责明确，便于长期维护和持续添加内容。

## 范围

- 网站公开访问，不实现登录或家庭权限系统。
- 维护者将照片、视频、封面、音乐及相册配置加入仓库，重新构建部署后更新网站。
- 网站不提供上传、删除、编辑相册等内容管理功能。
- 本期不使用业务后端、数据库或付费服务。
- 本期不开发原生 App，不实现社交、评论、点赞或 AI 识别。
- 不把前端密码框或隐藏链接描述为真实的访问控制。
- 未经用户明确指示，不推送代码或实际公开发布网站。

## 技术与部署约束

技术栈为 React + TypeScript + Vite，Node 24/npm 用于构建；依据 [前端基础决策](decisions/0001-frontend-foundation.md)。涉及技术边界变化时按 [SDD 指南](sdd.md) 记录并验证。

- 纯前端允许使用框架、TypeScript 和构建工具。
- 部署产物必须是静态文件，运行时不依赖 Node.js 服务。
- 避免不必要的依赖、过度抽象和提前引入原生平台能力。
- 同时支持本地开发、静态构建预览及 GitHub Pages 部署。
- 正确处理 GitHub Pages 仓库子路径、媒体资源地址、相册链接与页面刷新。
- 所有媒体地址由构建期 `VITE_MEDIA_BASE_URL`（生产默认值为 `https://cdn.jsdelivr.net/gh/MyNameLancelot/wangleyou@main/public/`）优先解析；变量未设置时回退 Vite `BASE_URL`。内容配置只保存 `media/...` 相对路径，禁止协议、绝对路径、反斜杠、查询、片段和目录穿越；此设置不改变页面 base 或 Hash 路由。
- 如使用路由，选择适合静态托管的方案，不依赖服务器动态重写。
- 提供 GitHub Pages 构建部署配置；部署方案中核实当前平台对仓库、文件与站点容量的限制，不假设可无限存储媒体。
- 发布配置以 main 为唯一发布分支，更新或手动运行时先验证再部署 dist/，默认地址为 /wangleyou/ 子路径；PR 和功能分支不自动公开发布。工作流配置完成不等于线上已经验证成功。
- 遇到实际媒体体积超出已确认方案约束时，说明问题及选项，不擅自改为外部存储或付费服务。

## 产品功能

### 4.1 首页与相册

- 首页由仅有的两个视口等高逻辑段组成：海滩首屏与“主回忆”。首屏展示网站名称、简短介绍、“开启回忆”和浏览全部影像入口；海边主题使用已确认的 2560×1440 海滩图，文字放在具备半透明纹理、背景模糊和阴影的可读玻璃卡片中；卡片不描白色边，靠模糊、色染与投影形成悬浮层次。
- 首页范围内，鼠标滚轮、触控板、触屏垂直滑动和非交互控件焦点下的 PageUp/PageDown/上下方向键，只能在相邻完整屏之间切换；小幅输入按 56px 阈值合并，切换期间忽略重复请求；第二屏内的横向滑动或触控板横向滚动用于换图，不切换两屏。减少动态效果时立即定位，正常模式平滑定位；原生 scroll snap 作为桌面兜底。不劫持按钮、链接、输入控件或查看器的键盘语义，也不接管非首页路由滚动。
- 主回忆只从源素材 `media-source/home-memory.json` 显式读取（构建期写入内容索引，运行时不遍历目录），数组顺序即播放顺序；第二屏保留居中照片、进度条与暂停后出现的播放按钮：照片以 3:2 相机画幅完整显示（不裁切）并浮在不带白色描边的毛玻璃底板上。桌面端另有左右箭头切换上一张/下一张，也可以按住鼠标左右拖动或使用触控板横向滑动换图（一次手势只换一张）；移动端不显示箭头而改为在第二屏内横向滑动切换。首页不显示标题、张数计数、常驻控制区、相册链接与查看器入口，两屏之间不渲染分隔线，并在交界带内用第二屏背景做跨屏淡入，两张背景之间不出现硬接缝；不支持遮罩时退回两屏直接相接。第二屏的左右箭头、播放按钮与进度条轨道同为可透视的毛玻璃表面（半透明色染 + 背景模糊 + 投影，无白色描边），进度条填充仍为主题色实色；不支持背景模糊时回退为更不透明的底色。区域以 `aria-label="主回忆"` 命名，进度条以 `aria-label="主回忆进度"` 命名。无可用照片时显示明确空状态；单张照片不创建自动播放计时器。
- 主回忆默认 2 秒循环，切换带约 600ms 淡入。仅当第二屏活动、照片数超过 1、页面可见、没有回前台待恢复、指针未停留、焦点未进入第二屏、用户未点击暂停且查看器未打开时运行；指针停留或键盘焦点进入时暂停，移开后恢复；用户显式恢复时可覆盖当时仍在播放器内的指针或焦点，直到指针移出或焦点离开。离开第二屏、页面隐藏、打开查看器或组件卸载时必须清理计时器；回前台不自动恢复。桌面与移动端点击照片都暂停自动播放，并在照片下方显示播放按钮；点击播放按钮或再次点击照片恢复播放。移动端的第二屏横向滑动只在第二屏内生效，纵向滑动仍切换首页两屏，音乐按钮上的触摸不计入换图。进度条是唯一的进度提示，自动播放不引入朗读。该局部首页状态不改变查看器 playback 的队列或意图。
- 支持多个相册；相册卡片以最多三张照片向右上错位层叠作为封面，第一张完整显示、后两张只露出上侧与右侧边缘，并展示标题、日期和简短描述。封面与留影页缩略图按普通相机横拍的 3:2 比例呈现，照片按原比例缩放完整显示、不裁切（非 3:2 的照片在框内留边）。
- 相册详情页按缩略图自身原始比例排布（不固定 4:3 框，也不裁切）：使用响应式 WebP `srcSet` 与 Masonry 布局，点击仍进入既有查看器。列数与间距沿用 `react-photo-album` 的默认响应式档位，按图库容器宽度取值：≥1200px 为 5 列/20px，600–1199px 为 4 列/15px，300–599px 为 3 列/10px，<300px 为 2 列/5px；对应桌面 1440 为 5 列、平板 820 与 1024 为 4 列、手机 390 为 3 列。`sizes` 由组件按实际列宽自动生成，主题不得手工覆盖。每张照片以白色相纸相框呈现：内边距 8px、圆角 8px、主题色轻投影（约 `0 5px 14px` 的近阴影叠加 1px 发丝阴影）；相框留白使用组件的 `padding` 参数并提供给库的列宽计算，因此相框不改变上述列数与间距档位，也不得叠加描边或边框。桌面详情 hero 的实际可见高度为 360–400px（内容区高度 `clamp(320px, 40dvh, 360px)`，标题区上边距 `clamp(48px, 8dvh, 72px)`），使 900px 高视口在首屏能同时看到更多图片；平板与手机沿用各自更紧凑的既有高度规则。
- 留影页（`#/browse`）以主题头图为 hero；平板与桌面在“留影”标题上方提供带左箭头的“返回首页”链接（跳转 `#/`，44px 命中区），手机（≤600px）不展示该入口、返回依赖浏览器返回手势，文案在 hero 剩余高度内居中。提供“全部 / 照片 / 视频”类型筛选和按年份分组的相册列表：每个相册一张卡，卡片沿用影像卡样式，说明条是紧凑单行并写相册名与相册说明；手机端说明条只渲染相册名，深色底框贴合文字长度（不铺满卡片宽度，也不保留相册名后的分隔线）；点击进入该相册。封面固定最多三层，直接采用构建期生成的媒体顺序取前三个可用缩略图；构建期先按 `topNN`（如 `top00`、`top01`）编号升序、再按其余文件名自然序排序，主题运行时不得另行排序。照片封面提供现有 WebP `srcSet`，按两列手机、两列平板、三列桌面卡片宽度选择 480w 或 960w；不为封面新增派生尺寸。每个相册该顺序下的前三张发布图片均为 3:2，层叠封面以 `cover` 铺满可见框，后两层只从右上方错位露出，不带白色描边或下方投影，鼠标悬浮时封面不缩放，强化相册而非单张照片的语义；该裁切不影响相册详情与其他影像的完整显示。同一年内按目录的 `YYYY-MM` 月份与 `sequenceNN` 顺序排列（00、01 …），年份分组从新到旧。类型筛选按相册内容判定：照片筛选保留含照片的相册，视频筛选保留含视频的相册。页面不展示媒体数量、年份数量、相册快捷列表、排序说明或键盘操作提示，卡片也不加逐张演示角标。内容区与 hero 共用同一最大宽度和左右边距，宽视口下定位栏与卡片不贴窗口边缘；900px 及以下隐藏左侧定位栏并改用页面内年份快捷导航。桌面端光阴刻度的年份按钮 hover 使用与当前类型筛选相同的主题主色和前景文字色。
- 相册内支持照片与视频混排：相册详情瀑布流把照片与视频排进同一条构建期顺序，视频缩略图使用派生封面（真实帧，或构建期占位封面），并由页面按媒体类型在缩略图正中叠加**中间凸起的通透玻璃按钮**式播放标识（半透明白色磨砂渐变 + `backdrop-filter` 模糊 + 顶部高光与柔和投影形成凸起感，内部是 `lucide-react` 的实心 Play 图标，图标为灰色；桌面 38px、手机 26px），点击后进入查看器播放。标识不烘焙进封面资源本身，因此留影页与相册索引的层叠封面保持干净。
- 留影页与相册索引的层叠封面按同一条构建期媒体顺序取前三个可用缩略图：照片用 `srcSet`、视频用封面 `posterSrcSet`；封面里的视频封面只呈现画面，不叠加播放角标（播放标识只出现在相册详情的媒体缩略图上）。
- 按拍摄日期组织内容，明确缺少日期时的回退与排序规则。
- 原始素材在仓库 `media-source/<相册目录>/` 中维护且不发布；照片与视频共用同一层目录结构，不设 `photos` 或 `video` 中间层。构建期按内容哈希生成 480/960/1600/2560 宽度 WebP 到 `public/media/<相册目录>/`，未变化图片不重编码；视频按内容哈希发布为同目录下的 MP4，源文件字节不变时目标已存在并跳过复制。本地与 CI 可缓存派生资源，缓存缺失时必须可完整重建。
- 视频发布形态是 H.264 + AAC 的 MP4（faststart），由维护者离线准备；HEVC、`.mov`、`.webm` 等素材先离线转码再入库，站点构建、CI 与运行时都不转码、不引入 ffmpeg/ffprobe。构建期只接受 `.mp4`，并对体积设基线：单文件 >100 MB 打印警告，>200 MB 构建失败（GitHub 普通推送本身也阻止超过 100 MiB 的单文件）。PC 浏览器、移动端浏览器与未来 WebView 共用这一种容器，不按端生成不同格式；`playsinline` 属性保证移动端内联播放，若将来要照顾弱网，做法也是补充同一格式的更低码率/分辨率变体，而不是换成 WebM/HEVC。
- 视频封面源素材是可选的真实帧：维护者在同一相册目录提供同名 `<视频同名>.poster.jpg`（也接受 `.jpeg`/`.png`/`.webp`）时，构建期走与照片相同的 WebP 派生管线；没有提供时构建期生成一张中立的占位封面（深色底纹、16:9，同样派生 480/960/1600 WebP），构建不失败，`video.poster` 与 `video.posterSrcSet` 始终指向派生资源。构建期不抽帧、不做视频解码；只有「封面源素材没有对应视频」、扩展名不在发布形态内、体积超限或封面候选比例与 `width`/`height` 不符才会让构建失败并指出具体文件与字段位置。
- 覆盖加载中、空相册、无内容、配置错误和资源加载失败等状态。

### 4.2 媒体查看（大图与视频）

- 相册页与全部影像页的大图查看与视频播放由全站共用的查看器组件提供（`src/media-viewer`，基于 `yet-another-react-lightbox` 3.32.2，启用 Captions、Fullscreen、Slideshow、Thumbnails、Video、Zoom 六个插件，外观与交互对齐该库官方 Full-blown 示例的库默认样式）；首页主回忆不接入查看器。**查看器是共用组件：两套主题只负责在会话存在时挂载它，不得覆盖其类名、样式，也不得复制出第二份查看器或增删其功能。**
- 查看器会话仍由 `playback` 唯一持有：共用查看器受控渲染 `open` 与 `index`，用户翻页通过库的 `view` 事件回写会话索引，查看器不保存第二份索引副本；关闭、路由变化或卸载时释放事件监听、媒体资源与计时任务，页面滚动锁随查看器关闭解除。
- 照片与视频在同一舞台内呈现：照片保持原始比例完整显示（`object-fit: contain`，不裁切主体），视频使用原生 HTML5 video 与浏览器控制条（播放、暂停、进度、静音与浏览器可用的全屏能力）；打开视频时尝试自动播放，被浏览器拒绝时由原生控件提供主动播放入口。
- 查看器背景为纯黑不透明底（库默认），查看器内不提供主题切换入口，主题只在页面级入口切换。
- 交互采用该库默认：**放大、缩小与关闭按钮在全端都不渲染**，工具栏（任何视口）只保留幻灯片与全屏；上一项/下一项按钮只在桌面（≥1200px）显示，手机与平板隐藏并改用触摸滑动；退出查看器依赖 Esc（桌面）与点击黑色背景，手机上依赖点击黑色背景与浏览器返回。缩略图带常显，可在其上方通栏的收起条上点击收起或展开；两端按钮在队列首尾禁用（不循环、不自动推进）；键盘左右方向键与触摸滑动切换；双击（双指）缩放。幻灯片只能由工具栏按钮显式启动（默认不自动播放），视频自然结束本身不会推进队列；桌面滚轮不再切换媒体；不再有自定义视频控制条与自定义加载失败/重试面板（加载失败显示库默认错误图标，用户可手动切换或关闭后重新打开）。
- 缩略图收起条：紧贴缩略图带上方、与屏幕同宽的一条可点区域，居中显示图标库（`lucide-react`）里的向下箭头表示“收起缩略图”，收起后同一位置显示向上箭头表示“展开缩略图”；该条不遮挡画面，画面与寄语为它让出底部空间。
- 共用查看器保留一条键盘契约：查看器打开期间 Tab 焦点在查看器内循环，库的模态语义把其余页面标记为不可达，因此 Esc 与方向键始终有效；键盘焦点环在查看器内固定为白色，不随主题变化。
- 照片寄语来自相册 `meta.json` 的 `photos_meta.captions`（可按文件名登记照片或视频，允许只覆盖一部分）：渲染为**当前影像左下角**的小玻璃条——按影像实际渲染尺寸定位，离影像左边与底边各约 12px，宽度贴合文案且不超过影像宽度减 24px（深色半透明底 + 背景模糊 + 圆角 + 左对齐文字）；没有寄语时不保留空位。
- 全屏只展示影像：进入全屏后工具栏、上一项/下一项、缩略图带、收起条与寄语全部隐藏；PC 全屏下键盘左右方向键仍可切图，手机与平板在全屏下仍可触摸滑动切图（进入/退出全屏后焦点交回查看器容器，键盘语义不丢）。
- 平台能力差异如实处理：查看器本身已经是覆盖视口的黑色沉浸层。浏览器不支持元素级 Fullscreen API 时（iPhone Safari 只支持 `<video>` 全屏），不渲染全屏按钮也不做假装全屏的替代；此时视频仍可借原生控件的全屏按钮进入系统全屏，图片则保持沉浸层，需要隐藏浏览器地址栏时依赖把站点“添加到主屏幕”（standalone）或未来的 WebView 套壳，这两条都属于后续里程碑。
- 点击影像、导航与媒体控件都不关闭查看器，只有真正的背景区域才关闭。
- 打开查看器时定位到所点击的媒体；单张相册两端按钮都禁用，不出现无效切换；空相册不进入查看器。
- 关闭后焦点回到打开查看器的触发元素；关闭、路由变化或卸载时清理事件、媒体元素与计时任务。
- 查看器沿用库默认工具栏（未启用计数器插件），因此界面没有可见的数量计数器；当前位置由库给当前影像的可访问名称（`aria-label`「第 N 项，共 M 项」）提供给读屏。若以后要显示可见计数器，需要按新的需求变更确认，而不是只在代码里打开插件。

### 4.3 视频与背景音乐

- 视频支持播放、暂停、进度调整、静音/取消静音及浏览器可用的全屏能力；音量由系统或浏览器控件控制。发布形态是 H.264 + AAC 的 MP4（faststart），只接受 `.mp4`，单文件 >100 MB 警告、>200 MB 构建失败。
- 移动端优先内联播放，不预加载全部视频文件。
- 查看器不实现自动幻灯片；视频结束停留当前项，必须由用户手动切换。
- 视频无法自动播放时显示主动播放入口，不跳过浏览器限制。
- 切换内容或关闭查看器时停止对应视频。
- 视频容器不在发布形态、体积超限或封面候选比例不符时在构建期失败并指出具体文件与字段位置（缺少封面源素材不再失败，改为构建期生成占位封面）；运行时加载失败显示查看器默认的错误状态，不出现无限跳过。
- 背景音乐当前由各主题目录维护固定私有资产，不进入相册内容配置；首次访问默认尝试播放，被浏览器拒绝时保持未播放视觉，任意首次点击或按键即恢复。提供暂停与音量控制（滑块可降到 0，等同静音）；音量是 playback 状态的一部分，audio 元素只投影该值，两个首页入口共享同一音量。播放意图与音量缓存于 `localStorage`（只写用户的显式切换与音量调整）：刷新后按缓存恢复，缓存为播放时先尝试自动播放，被浏览器拒绝则保持未播放视觉，任意首次点击或按键即恢复播放；缓存为暂停时刷新保持暂停；存储不可用时静默回退默认行为。
- 播放视频时暂停背景音乐；视频结束后仅在用户此前开启音乐且未主动关闭时恢复。背景音乐控件只挂在首页，离开首页后其 audio 元素随控件卸载，因此相册页打开视频时不存在第二路音源；回到首页仍按同一份播放意图与首次手势规则恢复。
- 首页两段整屏各自在右上角提供一个随屏移动的背景音乐按钮，两个入口共享同一 audio、播放意图和实际状态；第一屏主题按钮位于右下角并与第一屏音乐按钮保持同一条右侧中心线，第二屏不显示主题按钮。滚动只切换可见的音乐入口，不改变音乐播放意图或实际状态。音乐与主题按钮命中区均为 44×44px，音乐按钮可见毛玻璃圆形与主题按钮收起表面均为 32×32px，并使用约 18px 的边距及安全区避让；音乐按钮圆形与音量面板在首屏、第二屏都呈现可透视的磨砂玻璃，控件阴影只用 `box-shadow` 表达，不使用会隔离背景模糊取景的 `filter`。播放态显示普通音符，暂停态显示降强调的斜杠音符，不使用播放波纹；鼠标悬浮或键盘聚焦时仅图标组合轻微放大约 10%，同一时机在该图标正下方展开右边缘与圆形对齐、仅含滑块的（无喇叭图标）深色磨砂玻璃音量面板（音乐图标同色相的半透明色染 + 背景模糊，无白色描边；第二屏浅色背景上同样可透视），滑块为浅色细线轨道与纯白直角细长方形滑块，移开指针并移出焦点后收起；触屏端以长按音乐按钮作为音量入口，长按不切换播放状态，点击面板外或按 Esc 收起；音量入口只在音乐处于播放状态时可用，暂停时不展示也不进入键盘顺序；减少动态模式按全局规则立即切换。
- 播放状态有明确归属，避免多个音源同时播放。
- 关闭播放器后不得残留音频、视频或播放计时任务。

### 4.4 主题

- 至少实现两套完整主题；当前交付海边沙滩（站点默认外观）与旷野草原。
- 主题保持整洁、温暖、明亮的共同风格。
- 每套主题拥有独立的页面 UI（首页、留影页、相册页等）样式、装饰和资产；主题之间不得共享 React UI 组件、CSS 或主题资产。唯一例外是全站共用的媒体查看器：它属于 `media-viewer` 模块，两套主题只挂载同一个组件，样式与功能都不可按主题定制，也不得各自复制一份。
- 不显示常驻全局顶部导航；首页首屏从视口顶部完整呈现，页面内入口与返回链接承担内容导航。
- 每套主题独立提供毛玻璃主题切换按钮：首页按钮属于第一屏右下角，其他页面按钮属于页面顶部右侧，均随所属页面内容自然滚动离开，不使用 fixed 或 sticky；查看器不再提供内部主题入口。按钮默认只显示循环图标，毛玻璃圆形仅包住图标（20px 图标配 32px 圆形），实际命中区域不小于 44×44px；鼠标悬浮或键盘聚焦时展开为约 112px 胶囊，图标右侧显示“主题切换”，点击后按原规则保存并切换主题。
- 所有毛玻璃表面统一不使用白色描边或白色高光边。
- 海边主题首屏眉标文案为 `LeYou • Growing Moments`（实心圆点分隔），不设独立背景与内边距，并与标题左对齐；草原主题保留自身语气文案与样式。
- 首页首屏不显示媒体数量、相册数量或“内容均为演示”的统计说明。
- 主题覆盖页面、卡片、按钮与播放控件；查看器不在主题覆盖范围内（共用组件，见 4.2）。
- 保存主题偏好，刷新后恢复；本地存储不可用时正常降级。
- 保证文字对比度、焦点状态和控件可读性。
- 主题只共享无 UI 的领域类型、路由、播放状态和交互契约；首页两屏、主回忆、相册浏览与查看器的操作含义和可访问性标准保持一致。
- 新增主题不得导入另一主题的 UI、CSS 或资产；可见布局和视觉语言可独立演进。
- 主题设计需提供默认降级；关闭装饰、字体或动画后，页面和播放控制仍然清晰可用。

## 内容数据与维护

使用结构明确的静态配置维护内容，不在 UI 组件中写死实际相册数据。

相册字段至少包括稳定 ID、标题、描述、日期和媒体列表。媒体字段按类型包括：
- 稳定 ID、照片或视频类型、资源地址。
- 缩略图或视频封面；视频封面为必填字段（`poster`），并带同宽高比的响应式候选图 `posterSrcSet`。
- 可选拍摄日期、说明、替代文本、宽高及视频时长（当前相册照片与视频封面尺寸由构建期生成，视频画幅取自封面派生尺寸，不探测真实视频画幅）。

要求：
- 明确资源路径、排序、字段默认值及缺失字段的处理规则。
- 对配置错误、重复 ID 和不存在的本地资源提供可定位的校验信息。
- 相册配置是内容的唯一事实来源；主题等用户偏好可保存在本地。
- 新增相册只需新增 `YYYY-MM-sequenceNN-相册名` 目录、照片与 `meta.json`（`sequence` 必须小写），构建期自动发现，无须修改 UI 代码。
- 每个相册目录的 `meta.json` 支持两段：`album` 描述相册本身（`title`、`date`、`description` 均可选，`title` 缺省取目录名后缀，`date` 缺省取目录名的年月并允许只写到月，`description` 最多 16 个字符含标点）；`photos_meta.captions` 按文件名登记单张媒体寄语（照片或视频都可），数组项只允许 `fileName` 与 `caption`，`caption` 为 1–60 个非空白字符。出现两段以外的键、未知文件名或重复登记都会在构建期报错；`*.poster.<图片后缀>` 是视频封面保留名，不能登记寄语。
- 照片顺序与 ID 仍不写进 `meta.json`：构建期扫描目录，按 `topNN` 优先（编号升序）、其余按文件名自然序生成顺序，并由文件名生成稳定 ID；该 `album.media` 顺序是相册详情、留影页层叠封面及后续展示的唯一事实来源，同一相册内 ID 必须唯一。寄语允许只覆盖一部分照片。
- 提供演示相册、照片和视频，不依赖用户先提供真实家庭素材；演示相册在相册详情页元信息中标注“演示相册”，缩略图不逐张加演示角标；当前背景音乐是主题私有演示资产，来源未确认前仅用于非商业占位。
- 外部演示素材必须说明来源与使用条件，确保部署后的示例可以访问。
- README 说明缩略图、视频封面、视频离线转码与媒体体积基线的维护方式。

## 体验与性能

### 视觉与交互

- 合理留白，信息层级清晰，让照片成为视觉中心。
- 首页、相册页和播放器风格统一。
- 避免大量装饰、强烈渐变和复杂动画。
- 关键操作不能仅通过悬停触发，触屏按钮应易于点击。
- 全站展示文字与图片默认不可选择，图片不可触发原生拖拽；`input`、`textarea` 与 `[contenteditable="true"]` 等可编辑字段保留文字选择能力。若展示文本确有复制需求，须以具体功能的规格和样式明确声明例外。
- 所有主题的图片缩略图不显示外侧或图片内部描边，包括键盘焦点状态；唯一的例外是相册详情页的白色相纸相框，它是照片底衬而非描边，且该相框内不得再出现描边或边框。键盘聚焦时以轻微提亮（`filter: brightness()`）与约 2px 上浮作为替代焦点指示，不得出现“聚焦后看不出焦点在哪”的无指示状态；该焦点指示对相册详情的内联图库同样生效。缩略图仍须保留键盘可聚焦及 Enter/Space 打开查看器的操作语义。
- 全站交互元素的聚焦指示只服务于键盘导航：鼠标或触摸点击后，按钮、链接、表单控件、视频与对话框都不得残留任何浏览器默认聚焦框或描边（含黑色默认外框）；键盘导航获得的焦点必须给出主题色外圈，不允许出现“聚焦后看不出焦点在哪”的无指示状态。链接悬浮可以改变边框颜色，但不得变成深色或黑色描边。
- 按钮在任何状态下都不使用边框：按钮本身（含查看器内的关闭、上一项、下一项等控件）在默认、悬浮、聚焦、按下与禁用状态都不得出现边框或描边，透明占位边框也不允许；需要用底色、圆角、投影或字重表达层级与状态。按钮样式的链接同样适用；相册详情的白色相纸相框属于照片底衬，不属于按钮边框。
- 视觉与交互设计以用户最新口述和本文、活动变更规格为准；不维护外部设计稿作为产品或交互事实来源。
- 新页面、新流程、新交互语义、新组件或组件语义变化、主题变化及重要响应式变化，实施前须明确用户已确认的要求和验收项。
- 完全复用既有组件与交互语义的用户可见变化，仍须以浏览器实际结果核对；无用户可见影响的内部变化不增加设计流程。

### 兼容性与无障碍

- 覆盖约 360px 移动端、平板和常见桌面宽度，避免意外横向滚动。
- 适配横竖屏及移动端安全区域。
- 支持触屏、鼠标和键盘操作。
- 查看器正确管理焦点，关闭后恢复合理焦点位置；控件具有可访问名称。

- 如实记录已验证的浏览器及 WebView 适配限制，不声称未验证的兼容性。

### 性能与资源管理

- 列表优先加载缩略图，大图按需加载，合理预加载相邻媒体。

## 首版行为默认值与补充验收

以下默认值用于消除当前实现的歧义；后续变更应同步本文。

### 播放行为

- 打开查看器时定位所点击的媒体；照片与视频都以手动上一项、下一项、键盘方向键或触摸横滑切换，视频按浏览器能力播放。
- 单张相册不出现无效切换，空相册不进入查看器。
- 页面进入后台时暂停幻灯片、视频和音乐，返回前台不自动恢复，等待用户主动继续。
- 视频播放被浏览器拒绝时停留当前项并提供播放入口；媒体加载失败时显示查看器默认错误状态，用户可手动切换或关闭后重新打开。
- 背景音乐在首页两段播放。页面隐藏时暂停；回到前台不自动恢复，等待用户点击音乐按钮显式恢复。
- 明确区分用户播放意图、实际播放状态及系统临时暂停原因，不能只靠一个布尔值推断所有恢复行为。
- 快速切换时，旧媒体的异步加载结果、结束事件和播放请求结果不得影响当前媒体。
- 平台无法设置音量时采用系统音量控制，并提供可用的播放或静音能力，不展示无效控件。

### 内容规则与错误分层

- 相册按日期从新到旧，媒体按拍摄日期从旧到新；无日期项置后，同日期及无日期项保持配置顺序。日期不从文件修改时间推断。
- 相册 ID 全局唯一，媒体 ID 在所属相册内唯一；跨相册引用使用相册 ID 与媒体 ID 的组合。
- 描述、日期、尺寸等可选字段允许缺失；标题、类型、稳定 ID 和媒体地址必须有效。封面未指定时选首个可用缩略图或视频封面，空相册使用占位展示。
- 配置错误、重复 ID、显式引用的本地文件缺失必须使内容校验和构建失败，并报告配置位置；运行时网络失败采用页面内反馈，不使整个应用崩溃。
- 媒体原始素材、发布资源、生成文件应有明确归属；应用只引用发布资源，不直接遍历源素材目录。相册原始素材（照片、视频与视频封面源素材）位于 `media-source/YYYY-MM-sequenceNN-相册名/`（`sequence` 小写），由同目录 `meta.json` 与构建期索引描述；发布资源位于同名的 `public/media/YYYY-MM-sequenceNN-相册名/`，目录层级与源素材一致，照片派生 WebP、视频封面派生 WebP 与按内容哈希发布的 MP4 都在这一层；主题私有的首屏图、第二屏背景与背景音乐位于 `public/media/themes/<主题>/`，只由该主题代码引用，不进入相册配置。
- 缩略图、视频封面与视频发布方式由构建期脚本统一决定（输入是 `media-source/<相册目录>/`，输出是 `public/media/<相册目录>/`，派生目录不提交 Git）；脚本不得覆盖原素材。

### 必须覆盖的验收场景

| 场景 | 预期 |
| --- | --- |
| 横竖照片、视频混排 | 比例合理，布局稳定，大图不裁切主体 |
| 单张、空相册、相册边界 | 无越界、状态清晰 |
| 照片与视频混排 | 切换、播放与音源协调正确 |
| 后台切换后返回 | 所有播放等待用户继续 |
| 连续快速切换并关闭 | 旧事件不更新当前状态，无残留播放 |
| 自动播放拒绝、媒体错误 | 有主动播放或恢复入口，无无限跳过 |
| 本地存储不可用 | 默认主题可用，偏好操作不导致崩溃 |
| 错误配置与缺失本地资源 | 构建失败且能定位问题 |
| 仓库子路径及直接访问相册 | 资源地址、刷新、返回行为正确 |

浏览器验证记录版本、视口、操作和结果；移动端模拟不等于 iOS、Android 真机或 WebView 验证。
