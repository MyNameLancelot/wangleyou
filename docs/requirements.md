# 产品需求与验收基线

状态：已确认的完整产品需求。已实现手动照片浏览、内容维护基础、照片与视频连续播放、三套主题（默认/海边沙滩/旷野草原）切换与偏好记忆。自动幻灯片、背景音乐和 App 套壳尚未实现。本文维护当前产品基线；拟议变更先写入 `changes/`，实施并验证后同步到本文。

## 项目目标

网站中文名称为“王乐悠”，完整显示名称为“王乐悠 · 成长相册”。

本项目是记录孩子成长与家庭生活的纯前端影像网站，通过 GitHub 仓库管理源码、照片、视频和相册配置，构建后可部署到 GitHub Pages 公开访问。

核心目标：
- 浏览相册与生活照片，播放全屏照片幻灯片、生活视频和背景音乐。
- 兼容 PC 和移动端浏览器，为未来 App WebView 套壳预留适配边界。
- 界面整洁、大气、阳光、温暖，以家庭影像内容为中心。
- 工程按业务能力划分模块，职责明确，便于长期维护和持续添加内容。

## 范围

- 网站公开访问，不实现登录或家庭权限系统。
- 维护者将照片、视频、封面、音乐及相册配置加入仓库，重新构建部署后更新网站。
- 网站不提供上传、删除、编辑相册等内容管理功能。
- 本期不使用业务后端、数据库或付费服务。
- 本期不开发原生 App，不实现社交、评论、点赞或 AI 识别。
- 不把前端密码框或隐藏链接描述为真实的访问控制。
- 未经用户明确指示，不推送代码或实际公开发布网站。

## 技术与部署约束

技术栈已确定为 React + TypeScript + Vite，Node 24/npm 用于构建；依据 [前端基础决策](decisions/0001-frontend-foundation.md)。后续优先沿用已有方案，涉及技术边界变化时通过完整 SDD 记录。

- 纯前端允许使用框架、TypeScript 和构建工具。
- 部署产物必须是静态文件，运行时不依赖 Node.js 服务。
- 避免不必要的依赖、过度抽象和提前引入原生平台能力。
- 同时支持本地开发、静态构建预览及 GitHub Pages 部署。
- 正确处理 GitHub Pages 仓库子路径、媒体资源地址、相册链接与页面刷新。
- 如使用路由，选择适合静态托管的方案，不依赖服务器动态重写。
- 提供 GitHub Pages 构建部署配置；部署方案中核实当前平台对仓库、文件与站点容量的限制，不假设可无限存储媒体。
- 发布配置以 main 为唯一发布分支，更新或手动运行时先验证再部署 dist/，默认地址为 /wangleyou/ 子路径；PR 和功能分支不自动公开发布。工作流配置完成不等于线上已经验证成功。
- 遇到实际媒体体积超出已确认方案约束时，说明问题及选项，不擅自改为外部存储或付费服务。

## 产品功能

### 4.1 首页与相册

- 首页展示网站名称、简短介绍、精选照片、相册入口及近期内容入口。
- 首屏服务于内容浏览，避免过大的装饰区域。
- 支持多个相册，展示封面、标题、日期和简短描述。
- 相册内支持照片与视频混排，视频具有封面及清晰的播放标识。
- 按拍摄日期组织内容，明确缺少日期时的回退与排序规则。
- 使用响应式缩略图布局，为媒体预留比例空间，减少布局跳动。
- 覆盖加载中、空相册、无内容、配置错误和资源加载失败等状态。

### 4.2 照片查看与幻灯片

- 点击照片进入大图查看，支持上一张、下一张、关闭和当前位置提示。
- PC 支持方向键切换和 Esc 关闭；移动端支持左右滑动，避免干扰正常页面滚动。
- 支持自动播放、暂停、播放间隔调整及循环开关。
- 大图默认保持原始比例，不裁切照片主体。
- 支持全屏；能力不可用时降级为页面内沉浸式查看。
- 明确首尾边界、单张相册、空相册及非循环播放结束行为。
- 切换内容或关闭查看器时正确清理计时器。

### 4.3 视频与背景音乐

- 视频支持播放、暂停、进度调整、音量及浏览器可用的全屏能力。
- 移动端优先内联播放，不预加载全部视频文件。
- 幻灯片遇到视频时暂停照片计时；视频结束后按当前幻灯片播放状态继续。
- 视频无法自动播放时显示主动播放入口，不跳过浏览器限制。
- 切换内容或关闭查看器时停止对应视频。
- 视频格式不支持或加载失败时提供明确反馈。
- 背景音乐通过配置指定，由用户主动操作开启，提供暂停、静音和音量控制。
- 播放视频时暂停背景音乐；视频结束后仅在用户此前开启音乐且未主动关闭时恢复。
- 播放状态有明确归属，避免多个音源同时播放。
- 关闭播放器后不得残留音频、视频或播放计时任务。

### 4.4 主题

- 至少实现三套完整主题，建议为暖阳奶油、晴空浅蓝、自然浅绿。
- 主题保持整洁、温暖、明亮的共同风格。
- 通过统一设计变量管理颜色、字体、间距、圆角、阴影等。
- 主题覆盖页面、导航、卡片、按钮、查看器和播放控件。
- 保存主题偏好，刷新后恢复；本地存储不可用时正常降级。
- 保证文字对比度、焦点状态和控件可读性。
- 新增主题复用同一信息架构、组件语义、操作位置和可访问性标准，主要通过语义设计变量、主题资产和装饰 Slot 表达差异。
- 业务组件不得直接消费主题专属原始色，也不得为每个主题复制一套业务组件逻辑。
- 主题设计需提供默认降级；关闭装饰、字体或动画后，页面和播放控制仍然清晰可用。

## 内容数据与维护

使用结构明确的静态配置维护内容，不在 UI 组件中写死实际相册数据。

相册字段至少包括稳定 ID、标题、描述、封面、日期和媒体列表。媒体字段按类型包括：
- 稳定 ID、照片或视频类型、资源地址。
- 缩略图或视频封面。
- 可选拍摄日期、说明、替代文本、宽高及视频时长。

要求：
- 明确资源路径、排序、字段默认值及缺失字段的处理规则。
- 对配置错误、重复 ID 和不存在的本地资源提供可定位的校验信息。
- 相册配置是内容的唯一事实来源；主题、音量等用户偏好可保存在本地。
- 新增相册只需添加资源及配置，无须修改 UI 代码。
- 提供明确标记的演示相册、照片、视频和背景音乐，不依赖用户先提供真实家庭素材。
- 外部演示素材必须说明来源与使用条件，确保部署后的示例可以访问。
- README 说明缩略图、视频封面和媒体体积优化的维护方式。

## 体验与性能

### 视觉与交互

- 合理留白，信息层级清晰，让照片成为视觉中心。
- 首页、相册页和播放器风格统一。
- 避免大量装饰、强烈渐变和复杂动画。
- 关键操作不能仅通过悬停触发，触屏按钮应易于点击。
- Penpot 维护视觉、交互、组件和响应式设计基线；产品行为仍以本文和活动变更规格为准，设计稿不取代需求文档。
- 新页面、新流程、新交互语义、新组件或组件语义变化、主题变化及重要响应式变化，在实现前完成设计更新和审查。
- 完全复用既有组件与交互语义的用户可见变化，实现后对照设计基线验证，无用户可见影响的内部变化不要求机械更新 Penpot。

### 兼容性与无障碍

- 覆盖约 360px 移动端、平板和常见桌面宽度，避免意外横向滚动。
- 适配横竖屏及移动端安全区域。
- 支持触屏、鼠标和键盘操作。
- 查看器正确管理焦点，关闭后恢复合理焦点位置；控件具有可访问名称。
- 尊重系统减少动态效果的偏好。
- 对全屏、音频自动播放等能力进行特性检测与降级。
- 如实记录已验证的浏览器及 WebView 适配限制，不声称未验证的兼容性。

### 性能与资源管理

- 列表优先加载缩略图，大图按需加载，合理预加载相邻媒体。
- 图片懒加载，为媒体预留尺寸或比例空间。
- 不一次加载整个相册的原图或视频。
- 页面切换、查看器关闭和组件销毁时清理事件、计时器及媒体资源。

## 首版行为默认值与补充验收

以下为消除歧义的首版默认值；后续变更通过 SDD 记录调整。

### 播放行为

- 打开查看器时定位所点击的媒体，默认不启动幻灯片、视频或音乐；关闭再打开不恢复上次的自动播放意图。
- 幻灯片默认间隔 5 秒、循环关闭；用户可调整间隔和循环开关。照片加载完成后开始计时。
- 非循环播放到最后一项结束时停止，保留当前媒体；单张相册不创建无效切换计时器，空相册不进入播放器。
- 手动上一项或下一项保持幻灯片播放意图，取消旧计时并对新媒体重新计时；未开启循环时边界按钮禁用。
- 用户主动暂停幻灯片后，不得因视频结束而继续切换。暂停视频时，幻灯片停留等待；用户继续视频后才能在结束时继续幻灯片。
- 页面进入后台时暂停幻灯片、视频和音乐，返回前台不自动恢复，等待用户主动继续。
- 视频播放被浏览器拒绝时停留当前项，显示播放入口；媒体加载失败时暂停推进，提供重试、手动切换或返回操作。
- 背景音乐仅在查看器会话内播放。进入视频时临时暂停；视频结束或切回照片时，只有音乐意图仍为开启、页面可见且未因用户暂停或后台切换停止时才恢复。
- 明确区分用户播放意图、实际播放状态及系统临时暂停原因，不能只靠一个布尔值推断所有恢复行为。
- 快速切换时，旧媒体的异步加载结果、结束事件和播放请求结果不得影响当前媒体。
- 平台无法设置音量时采用系统音量控制，并提供可用的播放或静音能力，不展示无效控件。

### 内容规则与错误分层

- 相册按日期从新到旧，媒体按拍摄日期从旧到新；无日期项置后，同日期及无日期项保持配置顺序。日期不从文件修改时间推断。
- 相册 ID 全局唯一，媒体 ID 在所属相册内唯一；跨相册引用使用相册 ID 与媒体 ID 的组合。
- 描述、日期、尺寸等可选字段允许缺失；标题、类型、稳定 ID 和媒体地址必须有效。封面未指定时选首个可用缩略图或视频封面，空相册使用占位展示。
- 配置错误、重复 ID、显式引用的本地文件缺失必须使内容校验和构建失败，并报告配置位置；运行时网络失败采用页面内反馈，不使整个应用崩溃。
- 媒体原始素材、发布资源、生成文件应有明确归属；应用只引用发布资源，不直接遍历源素材目录。
- 首次内容方案必须决定缩略图及封面的手动或脚本生成方式，记录输入、输出、重生成方式和是否提交 Git。选择脚本时不得覆盖原素材。

### 必须覆盖的验收场景

| 场景 | 预期 |
| --- | --- |
| 横竖照片、视频混排 | 比例合理，布局稳定，大图不裁切主体 |
| 单张、空相册、非循环末项 | 无越界、无无效计时、状态清晰 |
| 照片 → 视频 → 照片 | 计时与音源按上述规则交接 |
| 用户暂停后视频结束 | 不擅自恢复幻灯片 |
| 后台切换后返回 | 所有播放等待用户继续 |
| 连续快速切换并关闭 | 旧事件不更新当前状态，无残留播放 |
| 自动播放拒绝、媒体错误 | 有主动播放或恢复入口，无无限跳过 |
| 本地存储不可用 | 默认主题可用，偏好操作不导致崩溃 |
| 错误配置与缺失本地资源 | 构建失败且能定位问题 |
| 仓库子路径及直接访问相册 | 资源地址、刷新、返回行为正确 |

浏览器验证记录版本、视口、操作和结果；移动端模拟不等于 iOS、Android 真机或 WebView 验证。
