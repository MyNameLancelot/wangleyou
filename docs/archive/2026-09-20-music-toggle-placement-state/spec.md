# 音乐按钮位置与状态视觉规格

状态：已确认

## 背景

当前首页音乐按钮固定在视口底部中央，主题按钮固定在右下角。用户根据实际运行截图确认，这两个悬浮控制应形成同一组右下角工具，音乐按钮放在主题按钮垂直正上方。当前音乐暂停后只移除播放波纹，按钮仍显示普通音符，静止画面中难以辨认播放与暂停状态。

## 目标

- 把两套主题的音乐按钮移动到主题按钮正上方，并保持右侧对齐。
- 让播放和暂停状态无需悬停即可清楚区分。
- 保持当前播放波纹、按钮尺寸、主题色彩、播放状态逻辑和无障碍语义。

## 非目标

- 不改变背景音乐资源、音量、循环、自动播放限制或视频打开时的暂停规则。
- 不改变主题按钮的尺寸、展开行为、位置或主题切换逻辑。
- 不把两个主题的 React UI 或 CSS 合并为共享组件。
- 不新增第三方依赖。

## 用户确认的交互与视觉

1. 音乐按钮与主题按钮在右下角组成纵向悬浮工具组；音乐按钮位于主题按钮正上方，两个 44×44px 命中区之间约留 12px，右侧中心线对齐。
2. 播放状态继续显示普通音符与现有向外扩散波纹。
3. 暂停状态不显示波纹，使用带斜杠的音符表达“音乐已关闭”，同时降低图标与玻璃底色的视觉强调。
4. 海边和草原主题分别使用自身配色和独立实现，操作语义一致。
5. 按钮继续使用动态可访问名称：“播放背景音乐”或“暂停背景音乐”，并保留 `aria-pressed` 状态。

## 行为和边界

- “暂停状态”由现有 `isBackgroundMusicPlaying(music)` 结果决定；不创建第二套 UI 状态。
- 视频打开、页面隐藏、浏览器阻止播放等原因使实际音乐未播放时，也应呈现暂停视觉，不误显示波纹。
- 斜杠属于图标视觉的一部分并对读屏隐藏，可通过现有 Lucide 图标或同一 SVG 内的装饰线表达。
- 两个按钮在桌面和移动端均不得重叠、越出安全区或引起横向滚动。
- `prefers-reduced-motion: reduce` 下播放态不执行扩散动画，但仍通过普通音符与带斜杠音符区分状态。

## 验收条件

1. 海边与草原首页中，音乐按钮均位于主题按钮正上方，右侧中心线误差不超过 2px，两个命中区垂直间距为 8–16px。
2. 播放时显示普通音符且存在播放态波纹元素；暂停时显示带斜杠音符且不存在可见波纹。
3. 点击按钮后，`aria-pressed`、可访问名称、音频暂停状态和可见图标同步切换。
4. 两个按钮的命中区均不小于 44×44px，在桌面与移动端不重叠、不横向溢出，并避让安全区。
5. 减少动态模式下不播放波纹动画，播放/暂停图标仍可区分。
6. 主题切换、首页两屏、查看器视频阻断音乐及现有背景音乐状态测试回归通过。

## 依赖评估

继续使用项目已有的 `lucide-react`。候选方案包括：普通音符叠加手写 CSS 斜线、使用暂停双竖线图标、使用 Lucide 的带斜杠音乐图标。最终优先采用 Lucide 已有图标（若当前版本提供），因为语义明确、描边风格一致且不增加包；若版本未提供，则在同一按钮内以装饰性斜线覆盖现有音符，不引入新依赖。

## 验证方式

- Vitest：既有背景音乐状态与视频阻断逻辑回归。
- Playwright：桌面和移动端核对两按钮几何、图标状态、波纹状态、点击后的音频与 ARIA 同步、减少动态降级。
- `npm run check`、`npm run build`、`npm run test:e2e`、`npm run check:sdd -- --worktree --base origin/main`。
