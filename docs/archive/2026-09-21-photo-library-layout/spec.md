# 照片目录布局

状态：完成。

## 目标

示例照片迁入 `public/media/photos/` 的相册目录；构建期自动发现相册，生成应用读取的索引。每个相册仅用 `meta.json` 补充照片元信息，首页主回忆只由 `home-memory.json` 明确配置。

## 已确认行为

- 相册目录命名为 `YYYY-MM-SequenceNN-相册名`，按年月和 `SequenceNN` 决定全站顺序，页面展示为新到旧。
- 构建脚本自动发现一级相册目录；维护者不写总索引文件。
- `meta.json` 仅以图片文件名为键记录可选的拍摄日期、说明和替代文本，不声明照片列表或排序。
- 构建脚本只发现受支持图片：`topNN.*` 优先并按 NN 升序，其余按自然文件名排序；此顺序是相册展示顺序。
- `home-memory.json` 显式记录首页照片的完整元信息和播放顺序，不从相册派生。
- 不生成或引用缩略图；照片只保存一份。主题资源不迁移。

## 异常和边界

- 目录名、`meta.json`、主回忆配置、重复 ID、未知元信息文件名或图片资源无效，构建校验必须失败并定位路径。
- 运行时加载生成索引或主回忆失败时保持既有配置错误状态，不白屏。
- `top` 前缀只影响相册展示，不覆盖主回忆的显式顺序。

## 验收条件

1. 6 张示例图位于三个 `YYYY-MM-SequenceNN-相册名` 目录，旧顶层图片与缩略图均无引用。
2. 新增相册目录后运行生成与校验命令，无需手写总索引即可在构建产物中出现。
3. 相册按目录时间倒序，目录内 `topNN` 照片先于其他自然排序照片。
4. 首页仅按 `home-memory.json` 的顺序显示，不受相册排序或日期影响。
5. 内容、主回忆、构建与两套主题的既有浏览行为验证通过。

## 非目标

不扫描线上目录，不创建 CMS、上传能力或缩略图，不改主题 UI 和查看器交互。
