# 首页两屏音乐按钮规格

状态：已确认设计，待书面复核

## 背景

上一变更将首页音乐和主题按钮都归入第一屏，滚动到第二屏后两个控件均离开视口。用户确认其中主题按钮的行为正确，但第二屏仍需要自己的音乐按钮。音乐按钮不能固定悬浮，而应分别属于两段整屏内容。

## 目标

- 首页第一屏和第二屏右上角分别提供一个音乐按钮，两个按钮随各自屏幕移动。
- 两个音乐入口共享同一播放意图、实际播放状态和 audio 元素。
- 主题按钮只保留在第一屏右下角，第二屏不显示主题按钮。
- 保留现有音乐按钮视觉、交互、尺寸和安全区间距。

## 非目标

- 不使用 fixed 或 sticky 让同一个音乐按钮悬浮贯穿两屏。
- 不创建第二个 audio 元素或第二套播放业务状态。
- 不在第二屏增加主题按钮。
- 不改变非首页音乐按钮范围、查看器主题入口或视频与背景音乐协调规则。

## 用户确认的行为

1. 第一屏右上角显示第一屏音乐按钮，第二屏右上角显示第二屏音乐按钮。
2. 两个按钮分别相对于各自的整屏内容定位；上下滑动时与所在屏幕一起移动。
3. 第一屏主题按钮仍位于第一屏右下角并随第一屏离开；第二屏没有主题按钮。
4. 任一音乐按钮切换播放或暂停后，另一个按钮在进入视口时显示相同状态。
5. 两个入口共用单一 audio DOM；滚动本身不暂停、重置或重复播放音乐。
6. 两个音乐按钮均保持 44×44px 命中区、32×32px 可见圆形、约 18px 顶部/右侧安全区、斜杠暂停态及 hover/focus 约 10% 图标放大。

## 设计

- 每套主题继续独立实现音乐 UI，不跨主题共享 JSX 或 CSS。
- 每套主题的音乐组件只创建一个 audio 元素和一组可见性/播放同步副作用，同时渲染两个使用同一命令与状态的按钮入口。
- App 提供覆盖首页两屏的页面内容层包装；两个按钮分别绝对定位在 `0` 与 `100dvh` 两段的右上安全区，不使用 fixed/sticky。
- 两个按钮使用可区分的测试标记和相同的无障碍名称；测试按所在首页段定位，避免把两个合法入口误判为重复业务状态。
- 音频加载失败、浏览器阻止播放、视频打开和页面隐藏的处理继续由现有音乐组件与 playback 契约负责，两个按钮只投影同一结果。

## 验收条件

1. 海边和草原首页第一屏、第二屏右上角各有一个音乐按钮；每个屏幕同一时刻只显示属于自己的按钮。
2. 从第一屏滑到第二屏后，第一屏音乐按钮和主题按钮离开视口，第二屏音乐按钮进入视口；第二屏没有主题按钮。
3. 在任一屏点击播放/暂停，切换屏幕后另一个按钮的 `aria-pressed`、图标和 audio paused 状态一致。
4. 首页只有一个 audio 元素；滚动两屏不会重新加载、暂停、重置或叠加播放。
5. 两个音乐按钮均非 fixed/sticky，尺寸、位置、安全区、hover/focus、减少动态和键盘操作符合现有要求。
6. 非首页不显示音乐按钮；非首页页面主题按钮随页面滚动，查看器内部主题切换继续可用。
7. 桌面 1440×900 与移动 360×800 无横向溢出，两套主题回归通过。

## 验证

- Playwright 覆盖两屏入口可见性、几何位置、单一 audio、跨屏状态同步和主题按钮仅第一屏。
- 运行 `npm run check`、`npm run build`、`npm run test:e2e`、`npm run check:sdd -- --worktree --base origin/main`。
