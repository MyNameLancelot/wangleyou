# 实施计划

## 影响模块

| 模块 | 变化 |
| --- | --- |
| `themes` | 从单套变量升级为三套模式；新增主题读取、切换、偏好持久化；CSS 变量名对齐 Penpot 语义 Token |
| `content` | 校验与类型补充视频时长、字体资源与配置异常信息；演示内容增加视频条目 |
| `playback` | 从照片会话升级为媒体队列：当前媒体、播放意图、实际状态、连续播放、进度、队列推进 |
| `media-viewer` | 支持视频元素、控制栏、进度与音量、全屏、控制栏自动隐藏、键盘与触控、横竖屏 |
| `albums` | 首页、影像浏览（年份分组）、相册详情、未找到页按设计重构 |
| `app` | 主题切换入口、继续浏览/继续播放、路由 `#/browse`、配置异常与离线提示、safe-area |
| `shared` | 媒体缩略图与骨架、类型标识、图标按钮等可复用件 |

## 依赖顺序

1. 主题运行时（themes）——其它阶段的样式基础，先做且独立可验证。
2. 内容与播放模型（content、playback）——决定查看器与页面的数据契约。
3. 页面结构（albums、app）——消费上面的契约。
4. 查看器与控制栏（media-viewer）——消费播放契约。
5. 状态、无障碍与响应式收尾。
6. 装饰资产接入。

每个阶段都可独立构建通过并提交，不把多个阶段混在一个提交里。

## Penpot 对照点

- Foundations：语义颜色、间距、圆角、动效与媒体查看器 Token 名称。
- 09 Responsive Screens：390 布局、年份定位与底部导航、查看器控制栏与安全区。
- 10 Interactive Prototype：流程 A（浏览→相册→查看器→下一项→退出）、B（视频播放→暂停→连续播放→全屏）、C（主题保持上下文）、D（媒体失败→重试/返回）。
- 12 Developer Handoff：React 属性建议、playback/viewer 边界、资源导出规则。

## 验证方式

- 每个阶段：`npm run check`（内容校验、类型、lint、单测）。
- 阶段 2 之后：`npm run build` 与 `npm run test:e2e`（构建产物上的桌面与移动端验收）。
- 阶段 4 之后：手动对照 1440 与 390 视口的查看器与主题切换，记录结果。
- 无障碍：键盘走查、`prefers-reduced-motion` 模拟、对比度抽查。
- 证据写入 `verification.md`：命令、视口、流程、结果与未验证项。

## 回退方式

- 主题：`data-theme` 缺省回退 `default`，删除偏好键即可恢复默认；变量迁移按阶段提交，失败时回退该提交。
- 播放：`playback` 保持纯函数与显式状态对象，若视频不稳定可只关闭视频入口而不影响照片链路。
- 查看器：控制栏与视频能力彼此独立，回退其一不影响另一。
- 页面：路由与页面组件按阶段提交，可单独回退而不动主题与播放模型。
- 不使用破坏性 Git 命令，不删除已归档的设计记录。

## 风险

- 视频演示素材需要体积可控且可离线播放；若素材缺失，用本地生成的短视频占位并在界面标注。
- 自动隐藏控制栏与键盘焦点可能冲突，需保证聚焦时永不隐藏。
- 390 视口下的年份定位与安全区容易溢出，需在 e2e 中断言无横向滚动。
