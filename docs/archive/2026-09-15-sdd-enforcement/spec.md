# SDD 维护保障规格

状态：完成。用户已确认完整提示词及组合方案，2026-09-15。

## 背景与目标

现有开发约定没有自动门禁，小修也要求三个文件，与实际姓名修正流程冲突。建立完整/轻量分类、仓库内变更声明、共享校验及 CI。沿用 [需求](../../requirements.md) 和 [架构](../../architecture.md)。

## 设计与边界

采用 AGENTS 约定 + JSON 声明 + 确定性检查 + CI + 人工语义审查。仅文档方案无法拦截；仅 hook 易绕过；不引入外部 AI 服务。远端保护单独给出配置步骤，不操作权限、不提交或推送、不改变应用功能。

每个 PR 至少新增或修改一份 docs/changes/*/change.json 或 docs/archive/*/change.json，声明覆盖整个 PR 的变更摘要、full/light 分类、理由、行为/架构影响、验证证据以及每类基线的影响。完整声明同目录必须有 spec、plan、tasks；轻量不要求三份。归档移动仍有效。多项声明由审查核对共同覆盖范围。检查不能推断语义，故轻量声明可能被错误填写，需审查。

历史记录不补造：引入机制的 PR 用当前声明说明初始功能已有历史归档；没有新声明的后续差异失败。检查不扫描旧归档强制套新结构。

## 验收

- AC1：有变更但缺少声明、full 缺少三份文件、无理由的 light 均失败。
- AC2：行为或架构影响为 true 时必须 full；合法 full/light 通过。
- AC3：文档影响声明齐全，更新项必须在差异中，引用存在且文档本地链接有效。
- AC4：PR 使用目标分支 merge-base 和完整差异；本地支持暂存快照和包含未跟踪文件的工作区。缺失基准明确失败。
- AC5：覆盖多提交、新增、删除、重命名和归档移动；校验从对应 Git 快照读文件，避免未暂存内容掩盖问题。
- AC6：CI 接入独立稳定名称的 SDD job；文档说明必需检查、绕过权限及未核实的远端状态。
- AC7：保留现有测试验证业务约束，增加模块公开入口与依赖方向检查；自动检查不替代语义审查。
