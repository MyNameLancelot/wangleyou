# 分支审查修复规格

状态：完成

## 背景

分支审查确认自动化验证通过，但发现四类问题：上次播放记录仍写入却没有继续浏览入口；首页滚轮接管没有覆盖悬浮主题开关；主回忆自动播放会持续触发 aria-live，单张照片仍创建计时器；部分过程文档和依赖验证记录与最终实现不一致。

## 目标

- 明确移除“继续浏览 / 上次播放”入口及其本地存储写入；首页只保留当前两屏与主回忆行为。
- 悬浮主题开关上的滚轮意图继续归首页两屏导航接管，不能停在中间位置。
- 主回忆自动播放不通过 aria-live 连续播报；暂停状态下手动切换才提供 polite 播报。
- 单张照片不创建主回忆自动播放计时器；空相册仍显示空状态。
- 删除无消费方的主题常量与主题应用入参，收缩公开契约。
- 移除不再被运行时引用的旧海滩背景资产。
- 修正依赖、设计资产和 README 中与实际实现不符的描述；删除过期过程文档。

## 非目标

- 不恢复共享 React UI，不改变主题目录隔离。
- 不新增业务后端、播放状态第二归属或主题间导入。
- 不引入共享音量控件；视频音量沿用系统音量控制，站点内提供静音/取消静音。
- 不重构两套主题的可见 UI 结构。

## 行为与边界

- App 不读取、写入或清除 `localStorage` 中的上次播放记录；已有旧 key 留在用户浏览器中但不产生行为。
- `HomePage` 不再接受或渲染 resume 相关属性；首屏按钮为“开启回忆”和浏览全部影像入口。
- 首页 wheel handler 判定有效目标时包含当前主题的 `[data-testid='theme-switch']`；查看器打开或非首页路由不接管。
- `shouldRunHomeMemoryInterval` 只在照片数大于 1 时授权 interval。
- 主回忆序号文本在自动播放时 `aria-live='off'`，暂停时 `aria-live='polite'`。

## 验收条件

- AC-1：源代码不再引用、写入或测试“上次播放”持久化；`app`、`playback` 基线文档不再声明该能力；首页无继续浏览入口。
- AC-2：主题开关上触发 wheel 事件时，首页按阈值在两屏间切换；桌面与移动浏览器无横向溢出。
- AC-3：两主题主回忆自动播放期间序号不使用 aria-live；暂停后手动导航使用 polite 播报；单张照片不创建 interval。
- AC-4：`docs/superpowers` 过期过程文档删除；设计资产 README 描述当前主题运行时结构；依赖验证记录如实说明海边首屏和两主题开关分别导入玻璃库。
- AC-5：无消费方的 `THEME_LABELS`、`THEME_SHORT_LABELS`、`THEME_HERO_ASSETS`、`THEME_COPY`、`ThemeAppProps.theme` 删除；未引用的 `public/media/theme/beach-hero.webp` 删除。
- AC-6：`npm run check`、`npm run build`、`npm run test:e2e` 通过，关键行为有自动化证据。
