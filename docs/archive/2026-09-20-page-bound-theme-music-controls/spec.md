# 音乐与主题按钮随页面滚动规格

状态：已确认

## 背景

音乐按钮目前固定在视口右上角，主题按钮固定在视口右下角。滚动首页两屏或其他长页面时，它们始终悬浮不动，与页面内容层产生割裂。用户确认两个控件都应属于当前页面，并随页面一起滚动离开视口。

## 目标

- 首页音乐和主题按钮都归属第一屏，进入第二屏时随第一屏滑走。
- 浏览、相册索引和相册详情等页面的主题按钮归属页面顶部区域，随页面正常滚动。
- 保留按钮现有尺寸、状态视觉、hover/focus、主题切换和音乐播放逻辑。

## 非目标

- 不在首页第二屏重复渲染音乐或主题按钮。
- 不把控件改成 sticky，也不在滚动后重新吸附。
- 不改变查看器内部已有主题切换入口。
- 不改变背景音乐状态、主题持久化或双主题隔离。

## 用户确认的行为

1. 首页音乐按钮位于第一屏右上角，主题按钮位于第一屏右下角；两者相对于第一屏定位，不使用 `position: fixed`。
2. 从首页第一屏滚动到第二屏时，两个控件与第一屏一起向上离开视口，第二屏不显示重复控件。
3. 非首页页面的主题按钮相对于该页面顶部区域定位，页面向下滚动时自然离开视口。
4. 首页之外不显示背景音乐按钮，延续当前仅首页提供音乐控制的范围。
5. 查看器打开后继续使用查看器内部主题切换按钮；页面内容层按钮不承担模态查看器内操作。
6. 右侧、顶部和底部间距继续使用约 18px 与安全区；音乐可见圆形 32px、命中区 44px，主题按钮既有收起/展开尺寸不变。

## 布局与状态边界

- 每套主题应用提供一个承载页面控件的内容层定位容器；首页容器以第一屏为定位上下文，其他路由以页面根内容为定位上下文。
- 控件仍由各主题独立实现，不抽取共享 JSX/CSS。
- 仅改变布局定位；主题状态仍由 App 持有，背景音乐状态仍由 playback 持有。
- 首页音乐 audio DOM 随主题首页应用存在；按钮滑出视口不等于卸载或暂停，音乐状态不因滚动改变。

## 验收条件

1. 两套主题首页第一屏中，音乐按钮位于右上角、主题按钮位于右下角，尺寸和右侧中心线保持既有要求。
2. 滚动到第二屏后，两按钮均离开视口且 DOM 中各只有一个实例；返回第一屏后重新可见。
3. 滚动不会暂停或重置背景音乐意图与实际播放状态。
4. 非首页页面向下滚动后，页面主题按钮随内容离开视口，不保持 fixed/sticky；查看器内部主题切换仍可用。
5. 桌面 1440×900 和移动 360×800 均无横向溢出，安全区与 44px 命中区保持。
6. 播放/暂停图标、hover/focus 放大、主题持久化、首页两屏和查看器回归通过。
