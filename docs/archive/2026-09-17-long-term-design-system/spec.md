# 长期 UI/交互设计系统规格

状态：实施中（规格已由用户确认）

## 背景

项目将从当前家庭照片浏览继续扩展视频、连续播放、多主题、更多页面和未来 WebView。现有 SDD 要求交互变化走完整流程，架构也要求主题使用统一设计变量，但尚未明确何时必须更新 UI/交互设计、Penpot 如何作为设计基线，以及设计稿、实现和文档如何保持同步。

当前 Penpot 文件已经表达海边沙滩、旷野草原两套主题及主要页面、状态和流程，但变量、组件和原型主要以可编辑画板与规范呈现，尚未形成适合长期扩展的原生 Token、Component Variant、组件实例和完整交互连线。

## 目标

1. 将设计影响评估正式纳入 SDD，使每次变更明确声明是否需要同步或更新设计。
2. 建立可扩展的 Penpot 原生设计变量、组件、模式、主题和原型体系。
3. 使新增主题主要通过变量模式和装饰资产完成，不复制业务组件或页面逻辑。
4. 使新增功能优先复用既有组件与模式，只在出现新交互语义时扩展设计系统。
5. 为 React + TypeScript 实现提供稳定的 Token、组件属性、状态和响应式契约。
6. 保持桌面浏览器、移动浏览器和未来 WebView 的统一交互与可访问性标准。

## 非目标

- 不在本变更中修改任何前端运行时代码。
- 不实现主题选择、视频播放或其他尚未完成的产品功能。
- 不引入业务后端、数据库、登录、在线 CMS、付费服务或原生桥接。
- 不使用真实家庭影像或未经许可的商业字体、图片、插画。
- 不推送代码、公开发布网站或修改远端仓库设置。

## 设计影响分级

每个 `change.json` 必须声明 `designImpact`：

### `none`

没有用户可见的视觉或交互变化。适用于内部重构、构建维护、无 UI 影响的配置调整。必须给出具体理由，不需要操作 Penpot。

### `sync`

用户可见结果发生变化，但完全沿用已确认的组件、Token、模式和交互语义。无需新增设计方案；实现后必须对照 Penpot 进行视觉、响应式和可访问性验证，并记录证据。

### `update`

出现新页面、新流程、新交互语义、新组件或组件语义变化、主题变化、重要响应式变化、重要空状态或错误恢复变化。实施前必须更新 Penpot，并在规格或计划中记录文件、页面、组件和原型入口；实现后再次对照验证。

纯文案修正如不改变层级、布局和操作含义可为 `sync`；导致布局、信息层级或操作含义变化时为 `update`。不允许以改动行数或文件类型规避设计影响。

## Penpot 文件结构

长期设计文件采用以下页面：

1. `00 Governance`：设计原则、设计影响分级、贡献流程、版本和弃用规则。
2. `01 Foundations`：网格、断点、安全区、排版、间距、圆角、边框、阴影、图标和动效。
3. `02 Primitives`：主题原始色、基础尺寸和不供业务组件直接消费的原始变量。
4. `03 Semantic Tokens`：跨主题稳定的语义变量及主题模式映射。
5. `04 Core Components`：导航、按钮、图标按钮、标签、卡片、提示、对话框和表单型基础控件。
6. `05 Media Components`：媒体缩略图、查看器、控制栏、进度、队列、字幕、音量和全屏控件。
7. `06 Patterns`：页面头部、内容分组、空状态、错误恢复、主题切换反馈、继续播放等组合模式。
8. `07 Beach Theme`：海边沙滩主题页面和主题专属资产。
9. `08 Grassland Theme`：旷野草原主题页面和主题专属资产。
10. `09 Responsive Screens`：1440、390 参考画板和必要的平板、横屏行为说明。
11. `10 Interactive Prototype`：可实际点击的核心流程和异常恢复流程。
12. `11 States & Accessibility`：状态矩阵、键盘、触控、对比度、字幕、替代文本和 reduced-motion。
13. `12 Developer Handoff`：React 映射、属性、状态转换、资源导出和 CSS Token 示例。
14. `13 Decisions & Changelog`：重要设计决策、迁移、弃用和版本记录。

页面、区段、组件、变量、图层和导出资源必须使用语义名称，不保留无意义的自动编号名称。

## Token 架构

Token 分为三层：

1. Primitive：原始色阶和基础数值，如 `primitive.ocean.700`、`primitive.spacing.4`。
2. Semantic：业务可消费的稳定含义，如 `color.action.primary`、`space.section`、`motion.standard.duration`。
3. Component：仅在共享组件确有独立契约时建立，如 `mediaViewer.control.background`。

业务组件不得直接依赖主题专属 Primitive。主题以 Penpot Variable Mode 表达，共享 Semantic Token 在不同模式映射到不同 Primitive。至少包含 `Beach`、`Grassland` 两个模式，并保留不依赖具体主题名称的默认降级值。

Token 覆盖颜色、字体、字号、行高、字重、间距、圆角、边框、阴影、遮罩、图标尺寸、内容宽度、断点说明、动效、媒体查看器和安全区。命名需能直接映射为 CSS 自定义属性。

## 组件架构

组件按职责拆为 Core、Media 和 Pattern，不建立单一巨型组件。组件变体轴仅在会改变布局或交互契约时存在：

- `size`：必要的桌面/移动尺寸差异。
- `state`：default、hover、focus、pressed、disabled、selected、loading、error。
- `density`：只用于确有信息密度差异的列表或队列。
- `orientation`：只用于查看器、轨道等横竖屏确有布局差异的组件。
- `platform`：只在浏览器和未来 WebView 确有安全区或容器差异时使用，不提前建立空变体。

页面画板必须尽量使用组件实例。可替换内容通过明确 Slot 表达；主题差异通过 Token、背景层和装饰 Slot 表达，不复制业务组件。

每个交互组件标注尺寸、间距、内容约束、响应式行为、状态条件、建议 React 属性、键盘和触控要求。弃用组件不得立即删除：先在名称和 Changelog 标记替代项，待实现和页面实例迁移后再移除。

## 主题扩展契约

新增主题必须完成：

1. 新建 Primitive 色阶和获准使用的主题资产。
2. 映射全部 Semantic Token，不允许业务组件出现主题条件分支。
3. 仅在背景、插画、边界图形和动效节奏需要时提供主题 Slot。
4. 验证无装饰时功能仍清晰可用。
5. 验证首页、浏览、详情、图片查看、视频查看、异常恢复及主题切换。
6. 验证 1440、390、横屏查看器、安全区、高对比度和 reduced-motion。
7. 在 Decisions & Changelog 记录新增映射、资产和例外。

装饰资产必须标记为 `required`、`optional` 或 `decorative`，并说明能否隐藏、裁切、平铺及其安全区域。

## 原型与状态

Penpot 中必须建立可实际点击的流程：

- A：首页 → 相册浏览 → 相册详情 → 打开图片 → 下一项 → 退出。
- B：首页 → 打开视频 → 播放 → 暂停 → 连续播放下一项 → 全屏/退出。
- C：任意核心页面 → 切换主题，保持 route、albumId、mediaId、queue、index、进度和播放意图。
- D：媒体加载失败 → 错误状态 → 重试或返回。

原型同时展示导航反馈、查看器开关、控制栏显示/隐藏、主题切换反馈和 reduced-motion 替代行为。两主题的控件位置和操作含义必须一致。

playback 是播放队列、当前媒体、播放意图、实际状态、暂停原因和调度计时的唯一所有者；viewer 只负责 dialog、焦点、手势、控制栏显隐、全屏 DOM 和命令转发。

## SDD 与交付流程

1. 规格阶段声明 `designImpact` 及判断理由。
2. `update` 在计划中列出 Penpot 文件、页面、组件、流程和状态；设计完成并审查后再进入前端实现。
3. `sync` 在计划中列出复用的现有组件或模式和实现后核对范围。
4. 实施中如果出现未覆盖的新交互语义，先更新规格、计划和 Penpot，不静默扩展范围。
5. 验证记录包含设计文件链接、设计版本或日期、视口、流程、可访问性检查和实现偏差。
6. 完成时同步需求、架构、受影响的 module.md、README、设计决策和 Penpot Changelog。

Penpot 是交互和视觉契约的事实来源；产品行为仍以 requirements 和本次 spec 为事实来源；架构职责仍以 architecture 和 module.md 为事实来源。设计稿不得取代产品或架构文档。

## 异常与降级

- Penpot 暂时不可访问时，`update` 变更不得宣称设计完成；可以继续规格澄清，但实现需记录阻塞并等待设计基线恢复。
- Token 或组件迁移不得使现有主题出现未映射值；缺失映射使用已定义的默认语义值并在验证中报错。
- 外部字体或资产不可用时使用已确认的系统字体和无装饰降级，不影响内容和操作。
- reduced-motion 下移除位移、视差、持续漂浮和高频动画，保留必要的即时状态反馈。

## 验收条件

- A1：AGENTS.md 和 docs/sdd.md 明确设计影响三级分类、触发条件和证据要求。
- A2：change.json 规范能够声明并检查 `designImpact` 及理由。
- A3：Penpot 文件具有本规格规定的长期页面结构和语义命名。
- A4：Penpot 中存在 Primitive、Semantic、Component 三层原生变量及 Beach、Grassland 主题模式。
- A5：核心与媒体组件建立为原生组件和必要变体，核心页面使用组件实例。
- A6：主题扩展不复制业务组件，并有完整接入与验证清单。
- A7：流程 A–D 可以在 Penpot 预览中实际点击完成。
- A8：状态、响应式、键盘、触控、字幕、替代文本和 reduced-motion 要求完整标注。
- A9：开发交付页提供 React 属性、playback/viewer 边界、CSS Token 和资源导出规则。
- A10：设计决策和 Changelog 记录迁移、弃用、主题例外及版本日期。
- A11：本次不包含前端代码变化，仓库构建产物和运行行为不变。
- A12：完成验证逐项记录证据，未验证项目不得标记通过或归档。

## 已确认决策

- 采用面向长期扩展的完整设计系统方案。
- UI/交互设计是 SDD 的条件性必需步骤，而不是所有变更的机械必需步骤。
- 主题复用共同语义和组件，不建立两套互不兼容的业务组件。
- 当前变更只更新设计治理、设计系统和相关文档，不修改前端实现。

## 未决事项

无。实施中的细节选择不得改变上述验收条件；如需改变范围，先更新本规格并取得用户确认。
