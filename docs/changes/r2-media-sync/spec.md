# 相册媒体 Cloudflare R2 同步规格

日期：2026-10-09。状态：已在 `feat/r2-media-sync` 实现，主同步与单文件配置验收完成，按用户最新授权提交、推送并创建 PR；正式相册尚未同步。

关联：[实施计划](plan.md)、[任务与验证](tasks.md)、[变更声明](change.json)、[当前架构](../../architecture.md)、[当前需求](../../requirements.md)。

## 1. 问题、目标与已确认要求

构建已将相册照片及 MP4 输出至 `dist/media/<相册目录>/`。需要本机维护工具将这些产物增量上传到已经准备好的 R2，并能更新内容和清理已删除的媒体。

用户已确认：

1. 有效脚本命令先重新执行 `npm run build`，等待成功后才扫描与同步；不要求维护者事先手动构建。
2. 只同步相册目录内的图片和 MP4。最新指令不需要 MP3，覆盖此前 MP3 候选及复制规则讨论。
3. `dist/media/themes/**` 完全排除，包括远端上传、覆盖和删除；文档、JSON、音频及非媒体文件也排除。
4. R2 的 `media/` 已授权脚本独占管理；实际操作继续收窄到相册图片和 MP4。删除整个相册时也能识别历史相册目录。
5. 用户最新要求密钥与目标配置统一位于项目 `.private/r2/config.json`；密钥只在本机加载使用，不传入前端、命令行或日志。
6. 文件可能较多；比较不下载远端媒体，不对每个普通对象逐个 HEAD。
7. 只提供一个无参数命令 `npm run r2:sync`，运行即完成重新构建、增量上传和自动删除，不提供预览或分开的清理入口。

目标是确定性、可重跑的维护工具。它不提供在线内容管理，不改变网站的图片/视频播放行为，也不将 R2 上传隐式加入现有 `npm run build` 或 CI 发布流程。

## 2. 技术选择

采用 Node 24 + TypeScript + 现有 tsx，新增构建工具依赖 `@aws-sdk/client-s3`，通过 S3 API 操作 R2；SDK 不进入浏览器产物。Node 的 crypto、流、子进程及文件系统足够承担扫描、MD5、构建和有界调度，不新增通用并发库。

| 候选 | 判断 |
| --- | --- |
| TypeScript + AWS SDK + MD5/ETag | 推荐；复用项目运行时，比较仅需分页列表，控制构建、限定目录和失败后清理顺序 |
| SDK + 远端 SHA-256 JSON 清单 | 支持分片但增加清单提交、恢复及多写入者问题；第一版不采用 |
| AWS CLI / rclone 包装 | 成熟的传输候选，但增加独立安装和配置；项目仍需定制构建与删除边界。参考其校验方式，暂不作为执行依赖 |

第一版统一单次 PUT，不自动分片、不使用客户自带加密。对象大小上限为 200 MiB（209715200 字节），与现有 MP4 构建上限一致；超过上限在任何远端写入前失败。图片也适用该工具上限，不改变原始图片处理规则。单次上传失败需重传整个文件，这是换取直接 ETag 比较和简单恢复的取舍。

MD5 用于自有媒体的变化检测与传输完整性校验，不承担身份认证或对抗恶意碰撞。后续若单文件上限、弱网重试成本要求分片，重新评估固定分片 ETag 或哈希 metadata 方案，不静默改变第一版比较规则。

## 3. 输入与操作边界

- 从脚本位置定位项目根目录，与启动时 cwd 无关；构建子进程 cwd 固定为项目根目录。
- 正式源目录固定为 `<项目根>/dist/media`，远端前缀固定为 `media/`。生产命令不接受运行参数；测试通过依赖注入使用临时目录和桶前缀。
- 相册第一层目录匹配现有命名 `YYYY-MM-sequenceNN-相册名`，年份四位、月份 01–12、序号两位、名称非空。操作范围函数同时用于扫描、列表过滤、上传和删除。
- 在匹配的相册目录内递归识别 `.jpg`、`.jpeg`、`.png`、`.webp`、`.avif`、`.gif`、`.svg` 和 `.mp4`，扩展名大小写不敏感；当前构建实际输出 WebP 和 MP4。支持额外图片扩展名仅限同步，不新增源素材解码能力。
- 保留相对路径、文件名、大小写及中文字符，统一 `/` 分隔；SDK 接收原始 key，不预先将中文 URL 编码。
- `dist/media/2026-10-sequence01-生日/a.012345abcdef.960.webp` 对应 `media/2026-10-sequence01-生日/a.012345abcdef.960.webp`。
- 本地拒绝相册扫描路径的符号链接、非普通文件、目录穿越和祖先链接逃逸；在扫描阶段报出具体路径，不沿链接上传数据。
- 远端 key 必须满足相同相册与扩展名边界，并拒绝空路径段、`.`、`..` 和反斜杠。不处理 `media/themes/**`、`media/SOURCES.md`、MP3、清单文件、目录占位对象或桶内其他资源。
- 删除范围根据所有远端合法相册目录判断，不只根据当前本地相册集合判断，避免本地整册删除后无法清理旧册。

## 4. 凭据和配置

凭据与目标统一从本机 `.private/r2/config.json` 加载；仓库只保留不含真实密钥的 `scripts/r2-sync/config.example.json`。顶层只允许 `bucket`、`endpoint`、`credentials`；credentials 只允许必填的非空字符串 `accessKeyId`、`secretAccessKey` 与可选 `sessionToken`。region 固定 auto，endpoint 必须是 HTTPS 官方 R2 S3 endpoint，不接受认证信息或查询串。不使用 VITE 或默认环境凭据链。

按用户最新指令撤销独立 AWS INI 文件/profile 方案。本机一次性读取旧静态 INI，原子写入权限0600的JSON，读回核对后删除旧文件；不打印密钥、不保留额外密钥副本。正式脚本直接向 SDK 传入经过校验的静态对象，不执行外部命令、角色或联网凭据链；移除不再使用的直接 credential-providers 依赖，不提供旧文件 fallback。构建失败前远端调用仍为0。

缺失文件、错误结构、额外运行参数、Node 非 24 或非法目标配置在预检时退出。参数错误不触发构建；唯一有效入口均强制构建。SDK 仅申请目标桶对象读写所需能力；脚本不创建桶、不修改公开访问、CORS、域名或缓存设置。

## 5. 命令与默认行为

已实现唯一命令：

```bash
npm run r2:sync # 重新构建 → 增量上传 → 全部成功后自动清理旧媒体
```

`r2:sync` 指向 `tsx scripts/r2-sync/cli.ts`。没有预览、上传限定、单独清理或运行参数；不在执行中要求交互确认。

- 启动命令即执行完整镜像同步，所有新增/变化文件上传与校验成功后自动删除多余的受管理对象。
- 正常成功构建确认当前相册没有任何媒体时，合法空集合也同步为空，自动删除远端受管理媒体。若生成内容仍引用相册媒体而扫描为空，属于产物不完整，失败并禁止删除；目录缺失或无法扫描也不能视为空集合。
- 上传并发固定 4，本地哈希并发固定 2；重试、超时和日志方式均为内部规则，不要求维护者传参数。此为初始配置，不表示已经测得最优值。

## 6. 固定执行流程

1. 预检命令参数、Node、配置与凭据格式，获取项目级独占运行锁。
2. 通过子进程执行 `npm run build`，继承当前 `SITE_BASE` 等构建环境，实时转发日志；不修改媒体前缀或用户环境文件。
3. 等待构建退出码 0，核对 `dist/index.html` 和真实 `dist/media` 存在，并复用 `scripts/validate-content.ts` 的 validateFiles 将本轮生成内容引用与 dist 中的实际媒体核对，再扫描完整相册媒体集合。失败时不读取远端、更不写入 R2。
4. 对各文件流式计算 MD5，记录 key、大小、相对路径及文件统计快照；读前/读后核对统计值，变化即失败。
5. 分页 `ListObjectsV2` 列出 `media/`，不设置 delimiter，循环 continuation token 到完整结束；过滤并构建远端 Map。遇到列表错误、重复/不前进的 token 或同 key 冲突时拒绝执行计划。
6. 计算新增、覆盖、相同、待核实与待删除集合；只有少数不能直接比较的对象才 HEAD。
7. 输出新增/更新/跳过/待删除摘要并写本地机器可读报告，然后继续执行；这不是需要确认的预览模式。
8. 有界并发上传新增/变化项，核实返回 ETag；全部上传和校验成功后自动进入删除阶段。
9. 删除前重新扫描本地路径集合与统计快照、重新列出远端；本地变化或远端 key/大小/ETag/LastModified 与预期执行结果不符则终止删除。单写入者约定是前提，不声称跨主机事务隔离。
10. 分批删除已核定的旧媒体，逐项检查响应，再次列表核对目标状态；成功时受管理集合与本地集合完全一致。
11. 汇总耗时、计数和失败，关闭流、终止/等待子进程、清理定时器、销毁 SDK 客户端并释放本轮拥有的锁。

源目录是最新构建的产物。本轮不修改既有生成器、源素材、内容索引或媒体排序；不从 `media-source` 直接上传原始素材。

## 7. 内容比较与首次接管

ETag 去掉外层引号；普通 ETag 必须是 32 位十六进制才能参与 MD5 比较，按小写规范化。必须同时比较对象大小。

| 状态 | 处理 |
| --- | --- |
| 本地有、远端无 | 新上传 |
| 同路径、同大小、普通 ETag 等于本地 MD5 | 跳过 |
| 同路径大小或普通 ETag 不同 | 覆盖上传 |
| 分片 ETag（如 `hash-3`）或未知 ETag | HEAD 查询 `sync-md5` metadata；可信值与本地一致才复用，否则标为重新上传 |
| 本地无、远端在受管理范围内 | 上传全部成功后自动删除 |

上传写入 `sync-md5` metadata（32 位十六进制）与 `sync-version=1`，供未来恢复/分片对象核实；普通比较不读取这些 metadata。异常对象只有 metadata 的 sync-version 等于 1 且 sync-md5 为合法完整 MD5 时才参与复用，其他结构视为无法确认；仅在脚本独占维护的前提下信任。人工改写数据却保留旧 metadata 超出约定，需重传以恢复。

R2 没有文件时直接上传；已有普通 ETag 文件时直接比较；不需要初始化远端 JSON 清单，也不下载远端媒体。对于已有未知上传方式的对象，无可验证哈希则重新上传一次。

MD5 一致不代表响应头一致，普通列表也无法逐项核实 Content-Type/Cache-Control。正常跳过只承诺内容一致，新上传/覆盖时写入正确响应头；第一版不提供单独的 metadata 刷新能力。实施前必须在测试前缀验证单次 PUT 的 ETag 与本地 MD5 一致；不满足时本方案验收失败，不能降级为只比较文件大小或跳过校验。

## 8. 上传、重试与响应头

- 使用 `PutObject` + 文件读取流，明确 `ContentLength` 与 Base64 `ContentMD5`；校验上传响应普通 ETag 等于本地 MD5。
- 每次重试重新打开读取流，不重用已经消费的流；PutObject 禁用 SDK 的隐式流重试，外层最多 3 次尝试，指数退避并带随机抖动。读取/数据校验失败不盲目重试，明确为失败。
- SDK 所有操作关闭隐式重试，适配器为列表、HEAD 和批量删除显式有限重试，最多 3 次尝试；认证、权限和参数错误立即失败。Put 成功但响应遗失时，重跑/重试相同内容是幂等的。
- 单次调用截止时间 10 分钟，超时中止；信号中断停止调度新任务并中止正在进行的请求。截止计时器归调用创建与清理，不留悬挂任务。
- JPG/JPEG 为 `image/jpeg`，PNG 为 `image/png`，WebP 为 `image/webp`，AVIF 为 `image/avif`，GIF 为 `image/gif`，SVG 为 `image/svg+xml`，MP4 为 `video/mp4`；默认内联展示。
- 由既有生成器产生的内容哈希 WebP/MP4 使用 `public, max-age=31536000, immutable`；其他固定路径图片/MP4 使用 `public, max-age=0, must-revalidate`。哈希命名由生成器保证，不将任意带点文件名识别为哈希产物。
- 固定 key 覆盖可能受 CDN 缓存影响。脚本只保证 R2 数据，不自动调用 Cloudflare purge；同路径更新、删除需要立即反映到公共域名时，维护者另外清理缓存。

## 9. 删除、故障恢复与发布顺序

删除对象按每批最多 1000 项提交 `DeleteObjects`；HTTP 成功不等于每项成功，必须检查 `Errors`。对象已不存在视为目标状态已达到；权限、锁定或网络失败返回失败，重跑后重新比较。

已上传对象在后续失败时保留，不以回滚名义删除有效新文件；构建、扫描、列表、上传或上传校验失败，本轮都不进入删除。删除部分失败无法撤回已删除对象，明确汇报并以非零退出码结束；重新构建同一正确版本并重跑可继续收敛。

本地锁位于 `.cache/r2-sync/run.lock`，在构建前获得，因为两个进程同时改写 dist 也会破坏比较。锁记录本机 PID 与所有者标识；进程结束只清理自身的锁。已有锁一律保守拒绝，确认本机旧 PID 已退出后才由维护者手动回收遗留锁，不按时间自动抢占。跨机器/Cloudflare 控制台写入必须避免并行；本工具不提供分布式锁。

用户选择一条命令立即完成镜像同步，因此自动清理与同步在同一轮完成，不等待网站发布。当前网站尚未切向 R2；后续迁移时必须处理旧站版本仍引用旧哈希资源的发布窗口。工具不发布网站或检测两个 Pages 版本，也不能在上传/清理之间保证站点无损切换；未来发布编排需另行设计，不能偷偷恢复多入口或附加参数。

恢复删除需从对应 Git 版本重新构建并重新运行同一条同步命令，不提供 R2 历史版本自动恢复；回退网站前先恢复旧版媒体。目录不存在、无法扫描或目标错误时停止，不通过运行参数绕过。

## 10. 性能、日志与退出码

设本地选中媒体 N 个、总大小 B 字节，远端 `media/` 下对象 M 个、变化文件 U 个，比较为本地 O(B) 读取 + O(N+M) Map 操作；普通比较远端请求约为 `ceil(M/1000)` 页，具体页数以服务返回为准。非媒体对象仍占列表页，但被过滤后不操作。哈希不依赖重建后易变化的 mtime，也不根据文件名中截断哈希直接跳过内容比较。

实际上传仅 U 个文件；最多 4 个上传流并发，内存不随视频总字节数增长。自动清理前后有额外的远端列表核对，不将比较页数误报为整个同步请求数。更改文件需要在 MD5 后再次读取用于传输；以额外本地读取换取 ContentMD5 校验。

每阶段记录构建、扫描/哈希、列表/核实、上传、删除、总耗时；报告新增/覆盖/跳过/核实/删除/失败计数、待传及已确认成功字节数、列表页数与尝试数。终端显示摘要及最多 20 条失败，完整计划和结果写入忽略的 `.cache/r2-sync/latest-report.json`，不打印全部文件、不提供额外日志参数。报告写入失败在远端变更前终止；后置报告写入失败非零退出并明确远端可能已变更。

报告不保存密钥、Authorization、SDK 请求对象或签名 URL；只保留安全的目标名、key、大小、结果及经过过滤的错误码。

退出码：0 完整同步成功；1 构建、文件、网络或同步失败；2 额外参数/配置/运行时错误；130 用户中断。脚本失败时不调用 npm/Git 发布操作。

## 11. 非目标与基线影响

本次不新增 MP3 构建复制或播放，不修改现有媒体生成器、页面及原生壳；不移除 dist 媒体、不更改 Pages 构建、不配置 CORS/Range/自定义域名，不改 `VITE_MEDIA_BASE_URL`，不接入自动 CI 上传、不发布网站。

未来将线上媒体切向 R2 是独立部署工作：现有媒体 URL 入口已支持媒体前缀，但全局前缀也影响未上传的 themes 资产，需要独立决定主题资源同源策略、缓存、CORS、MP4 Range、根/子路径及 WebView 验证。不能仅设置全局 R2 前缀就宣称迁移完成。

工具已实现，模块契约、需求、架构、README 与 ADR 0008 已同步；正式相册同步和线上迁移未执行。实际验证见 tasks，方案历史不替代本轮证据。

| AC07 | 分片/未知 ETag 不直接当 MD5；metadata 可确认则复用，否则统一单次 PUT 重传；无远端 JSON 清单 |
| AC08 | 唯一入口为无参数 r2:sync，正常运行自动完成上传及删除，无预览/清理入口和交互确认；额外参数被拒绝 |
| AC09 | 超限、源缺失、产物不完整、文件变化、列表/上传/校验失败拒绝删除；构建确认的合法空集合自动清空受管理媒体 |
| AC10 | 流重试重建、最大尝试数与并发上限有效；认证错误不重试；部分删除错误明确返回非零，重跑收敛 |
| AC11 | 锁在构建前生效；信号中断清理自己持有的资源并阻止新删除；跨进程/远端变化被检测，不宣称分布式事务 |
| AC12 | 新上传/覆盖的图片与 MP4 Content-Type、ContentMD5、缓存策略正确；MD5 跳过不承诺 metadata 验证，不另设刷新入口 |
| AC13 | 大数量夹具和真实测试记录阶段耗时、请求数、字节数与内存情况，无硬编码“很快”的指标，无敏感日志 |
| AC14 | Node 24 下工具测试、check、build、SDD 通过；静态根路径/仓库子路径媒体仍存在；实际 R2 验证证据明确，未迁移线上 |

## 13. 实施前决策与资料

- 凭据文件解析格式：任务 1、任何联网之前本机识别并更新规格；不能暴露值。官方 provider 若必要，依赖版本以锁文件为准。
- 单次 PUT ETag 可用性：真实测试写入前缀的首个已知文件，验证后才接受生产比较逻辑；验收失败先修订方案，不能取消校验。
- 测试目标：真实写入前使用独立测试桶或本地配置的隔离测试前缀，生产 CLI 不提供任意前缀；测试产物清理仅限本轮创建对象。
