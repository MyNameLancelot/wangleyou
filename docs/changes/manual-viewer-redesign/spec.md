# 手动媒体查看器重构

## 问题

当前查看器把图片、视频、连续播放开关和视频工具混在同一控制区。`playback.openSession()` 默认开启连续播放，视频自然结束会进入队列下一项，违背本次手动查看要求；现有控制层也未按图片与视频的不同任务分层。

## 目标

- 在相册详情中点击任意照片或视频，保持路由、滚动位置和打开触发点，并在唯一 playback 会话中定位该媒体。
- 两主题各自重做查看器：图片使用“静默舞台”，视频使用“影院舞台”；两者共享队列和手动导航语义，但不共享控制层视觉。
- 提供上/下一项、位置提示、关闭、桌面键盘、移动横滑及可靠的加载/失败/无 poster 状态。
- 默认不循环；不实现自动幻灯片、自动轮播或视频结束自动进入下一项。

## 非目标

- 不改变相册内容结构、排序、路由、主题偏好、首页主回忆或背景音乐行为。
- 不新增依赖、后端、数据库、登录、上传、原生桥接或第二套查看器页面。
- 不把 Session 或媒体播放业务状态移入主题组件。

## 已确认设计

### 共用交互契约

- 查看器以 modal dialog 呈现。打开不修改 Hash 路由、不滚动页面；关闭、路由变化和卸载均关闭会话、解除滚动锁、退出全屏并恢复打开媒体按钮的焦点（触发点不再存在时回退到 `main`）。
- 顶部显示 `当前序号 / 队列长度`、主题切换和明确的关闭入口。桌面关闭入口位于右上角，使用可见的 `×` 与“关闭”；窄屏保持至少 44×44px 的 `×` 命中区。
- 第一项禁用上一项、最后一项禁用下一项；`stepSession()` 越界保留原会话。键盘 `ArrowLeft`/`ArrowRight` 切换，`Escape` 或关闭按钮退出。
- 移动端只在查看器媒体舞台的单指、横向位移超过阈值且显著大于纵向位移时切换；按钮、范围输入和 video 原生控件开始的手势不触发切换，纵向拖动与点击不被阻断。
- 查看器预加载下一张照片。图片、视频和 poster 地址继续唯一通过 `content.mediaUrl()` 取得；每次媒体 ID 改变时重置主题局部加载尝试和 DOM key，使旧异步事件不能回写当前会话。

### 图片：静默舞台

- 图片保持完整原始比例，以媒体为视觉中心；没有播放、进度、静音或全屏视频工具。
- 仅显示弱化的上/下一张按钮、顶部位置/关闭/主题入口，以及可选图片描述。描述存在时在媒体下缘居中可读地显示；无描述时不保留空白区域。
- 图片加载时显示主题私有的可读 loading 提示；失败时显示错误、重新加载、可用的手动切换和关闭路径；空队列不打开 dialog。

### 视频：影院舞台

- 视频在独立的暗色影院容器中播放，位置和关闭在容器顶部，描述位于视频下缘上方。
- 进度是紧贴视频下缘的可拖动时间轴，不是按钮。底部工具区仅对视频显示播放/暂停、时间、可辨识的 `Volume2`/`VolumeX` 静音状态以及全屏。
- `playsInline`、`preload="metadata"`、poster、字幕、加载、浏览器阻止播放、错误与重试保持可用。缺少 poster 仍显示可读影院背景、视频名称和播放入口。
- 视频的 `ended` 只将当前项标为结束并停留原位；用户必须显式按下一项或使用键盘/手势切换。

### 主题、响应式与无障碍

- Beach 在自身目录实现深海蓝、圆形轻磨砂的图片静默舞台和视频影院舞台；Grassland 在自身目录实现独立的草地色调、布局与 CSS。两目录不得互相导入 JSX、CSS、组件或资产，且不新增共享 React UI。
- 覆盖 1440px、768px 与 390px。移动端所有可点击入口不低于 44px，布局不产生横向溢出；视频的进度与工具在窄屏重新排布，不机械压缩桌面浮层。
- 所有控件有可访问名称和可见焦点；dialog 保持焦点循环。`prefers-reduced-motion` 时取消非必要过渡与控制层隐藏动画。

### 复看后确认的调整（2026-09-22 用户反馈）

- **查看器内不提供主题切换入口**：主题只在页面级入口切换；查看器不再接收主题切换命令。
- **关闭入口只有图标**：可访问名称仍是“关闭查看器”，不再有可见文字。
- **背景是纯黑不透明层**：不使用照片、渐变或图片纹理，也不使用 `::backdrop` 的背景模糊。
- **媒体不做透明度合成**：照片不使用淡入 opacity 过渡、不使用 `filter`，也不再用 `visibility` 切换显示。Chrome 复现显示：媒体元素在模态 `::backdrop` 背景模糊下做透明度合成时，整个媒体框会留下一层发亮的后备层；改为不透明纯色底 + 不透明媒体后消失。
- **纯黑背景 + 可读寄语**：照片寄语来自 `meta.json` 的 `photos_meta.captions`，渲染在画面正下方并随媒体整体居中；没有寄语时不留空位。
- **桌面滚轮切换**：累计 40px 阈值、420ms 冷却，一次滚动只前进一项；低于阈值忽略，视频进度条区域不参与切换。
- **移动端只用滑动**：不渲染上一张/下一张按钮；从进度条或控件区开始的触摸不触发切换。
- **焦点策略**：打开时聚焦对话框本身（不聚焦按钮，避免鼠标打开就出现焦点环）；Tab 焦点环只包含当前真正渲染出来的控件；重试按钮卸载后把焦点交回舞台。

### 代码审查反馈修正（2026-09-22 第二轮回看）

- **预加载依赖收窄**：两个主题的相邻照片预加载只依赖下一张照片的 src；此前依赖整个 `session`，视频 `timeupdate` 会不断产生新会话对象，反复清理并重建 `Image()` 使预加载失效。
- **按输入能力而非宽度判断触摸设备**：导航按钮的显隐改用 `@media (hover: none) and (pointer: coarse)`，因此手机横屏（宽度大于 600px）仍是“只用滑动”；窄屏 media query 只保留字号与留白压缩。新增横屏用例覆盖该行为。
- **alt 不再重复寄语**：`alt` 回退为 `alt → description → 相册照片`；寄语已显示在画面下方，避免读屏重复同一句话。
- **清理误导信息**：两套主题查看器 CSS 顶部注释改为“纯黑不透明底”，删除已不存在的 `.counter` / `.position` 死样式。

### 内容字段：照片寄语

`meta.json` 新增可选的 `photos_meta.captions`：

```json
{
  "album": { "description": "小小的你，第一次和我们见面。" },
  "photos_meta": {
    "captions": [
      { "fileName": "top01.jpg", "caption": "黄昏把树影拉得很长。" }
    ]
  }
}
```

- 数组项只允许 `fileName` 与 `caption`；`fileName` 必须是该相册目录里真实存在的图片文件名，重复登记同一文件报错；`caption` 必须是 1–60 个非空白字符。
- 寄语允许只覆盖一部分照片；不改变照片顺序、ID 或封面选择。
- `photos_meta` 只支持 `captions`，`meta.json` 顶层只支持 `album` 与 `photos_meta`。
- 寄语落到生成内容的 `Media.caption`，查看器优先显示 `caption`、回退 `description`。
- 演示内容在 `2025-05-sequence00-周岁` 相册中 mock 了 4 条寄语（覆盖 8 张中的 4 张），用于演示可选性。

## playback 契约调整

- `Session` 不再有 `continuous` 状态，公开 API 不再导出 `setContinuous`，主题命令不再含 `toggleContinuous`。
- `openSession()`、`stepSession()`、当前项、播放意图、状态、进度和时长契约保持；`handleEnded()` 无条件在当前项设置 `intent: 'paused'`、`status: 'ended'`、`progress: 1`。
- 这是为落实“手动推进”所必需的核心契约收敛，非 UI 可单独实现的改动。

## 验收条件

1. Beach 与 Grassland 的相册详情任一媒体点击后均打开查看器，并准确定位被点媒体（位置写进 `data-media-position`/`data-media-count`，界面不显示计数器）；路由、页面滚动位置与关闭后的焦点恢复正确。
2. 鼠标按钮、左右键和符合阈值的移动横滑都能在照片/视频混合队列中手动切换；首尾禁用且不越界，手势不影响按钮、视频控件、普通点击或纵向滚动。
3. 图片为无视频控制的静默舞台，带可选描述、加载和可重试失败状态；视频为独立影院舞台，进度紧贴视频底部且仅视频出现播放、时间、扬声器静音和全屏。
4. 视频自然结束不改变队列索引，不自动开始下一项；查看器没有自动幻灯片、自动轮播或连续播放开关。
5. 视频加载、播放阻止、失败/重试、无 poster 与图片失败均有可读恢复路径；快速切换、关闭或路由变化后旧媒体事件不更新新会话。
6. 两主题的查看器实现与 CSS 完全隔离；不新增依赖，所有地址使用 `mediaUrl()`。
7. 在 1440px、768px、390px 视口没有横向溢出，触控目标、键盘焦点和 reduced-motion 行为可用。
8. `npm run check`、`npm run build`、构建产物上的 `npm run test:e2e` 通过；`npm run preview` 的仓库子路径和 Hash 相册深链经浏览器核对。真实浏览器与模拟器验证结果如实记录。

## 依赖与实现评估

- 已有实现：React、原生 `<dialog>`、`<video>`、Pointer/Touch 事件、CSS media queries、`lucide-react` 都已覆盖所需能力。
- 候选：引入轮播、手势或视频播放器库会增加包体、不同主题 UI 耦合和资源生命周期复杂度；浏览器原生能力已满足本次手动交互。
- 选择：删除连续播放领域开关，两主题各自使用原生平台能力和私有 JSX/CSS；零新增依赖。回退时恢复本次涉及的 playback 会话、主题查看器和文档即可。
