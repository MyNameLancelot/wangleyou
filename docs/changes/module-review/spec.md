# 全模块审查规格

状态：审查完成，修复尚未实施。2026-10-01 用户已授权执行计划；使用只读审查、临时合成素材、现有检查与本地构建形成证据，不修改应用、测试、构建配置或原生代码。设备及真实后台等未验证范围见 findings，不视为功能验收通过。

## 问题与目标

用户要求全面检查各个模块，找出需要优化、拆分、重构和 bug 修复的地方，先 write plan。目标是获得覆盖全仓能力的证据清单和有优先级的行动建议，避免只盯大文件、只跑测试或无依据地重构。

审查依据是 [需求](../../requirements.md)、[总架构](../../architecture.md)、各 module.md、当前代码及实际行为；文档与实现不一致时先确认事实来源，不能直接修改需求来掩盖实现缺陷。

## 范围

- 前端：app、albums、content、playback、media-viewer、themes/book、shared，含公开入口、CSS、静态资产引用与保留但停用的音乐代码。
- 工具：媒体索引/派生/发布校验、离线照片压缩、静态验收服务器、SDD 校验；检查配置、缓存和文件读写归属。
- 原生：Android 容器与 StartupOverlay、签名输入/打包脚本、iOS 容器源码/工程的静态检查。
- 工程：网站/原生工作流、Vite/TypeScript/ESLint/Playwright 配置、依赖使用、测试与模块文档。
- 只读取素材目录命名和配置；合成边界素材用于临时复现。不整理或修改真实家庭影像、签名材料、设备 ID、已发布安装包。

## 非目标与约束

- 写计划阶段已完成；当前执行审查并交付 findings/action-plan，应用修复仍属于后续独立任务。
- 不改变页面设计、交互或内容结构，不引入后端、数据库、登录、付费服务或原生桥接，不推送/发布。
- Node 24/npm，静态根路径和 `/wangleyou/` 均是验证对象；不顺带升级依赖。
- playback 继续拥有唯一查看器业务状态，首页局部状态独立；主题 UI 留在 book，media-viewer 保持唯一共用实现。
- iOS 已暂缓：本轮及审查阶段只做源码/工程静态核对，不恢复编译、签名或设备交付。真机不可用时只记录缺口，不伪造结果。
- 上一文档清理未提交，保护现有改动。两项记录不合并；文档基线先使用当前工作区版本，审查执行时记录实际提交和差异。

## 审查判定

每个模块均给出“保留 / 修复 / 拆分 / 重构 / 暂不处理 / 需验证”之一或多项结论。保持现状也是有效结果，不能为了让每个模块都有修改而寻找理由。

每个问题包含：编号、模块、类别、代码位置、触发场景、预期/实际、证据强度、优先级、建议、验证方式、文档影响、回退与依赖。静态事实、代码推断、已复现缺陷、未验证范围分别标注。

- P0：明确的数据损坏、素材误删或正式交付被阻断，优先停止影响行为并处理。
- P1：可复现的用户流程/媒体状态/内容构建缺陷，先修复再考虑结构优化。
- P2：有可测收益的性能、职责/依赖/契约问题和重复实现。
- P3：局部可读性或低收益维护建议，可不实施。

优先级须依据实际触发与影响调整，不仅凭静态猜测升级。拆分需说明独立职责、状态与资源归属、最小公开接口、依赖方向、收益和回归成本；仅行数高、文件多、测试慢或形式相似不构成理由。

## 验收条件

- AC1：覆盖全部上述能力，模块矩阵无遗漏；没有问题的模块也有保留理由。
- AC2：所有拟议 bug 有复现证据或明确待验证标签，不把猜测写成确定缺陷。
- AC3：逐项检查状态/事件/计时器/媒体/异步任务的创建、失效和清理；静态根路径/子路径与输入错误边界有验证安排。
- AC4：每项拆分/优化有候选方案、选择条件、收益/风险与可执行验证，不机械增加依赖。
- AC5：产出按优先级和依赖排序的行动清单，说明 light/full 归类及需要同步的基线；改变已确认范围才请求新的用户确认。
- AC6：保留原生、浏览器模拟与真机差异，iOS 暂缓和设备缺口真实。
- AC7：写计划阶段完成规格、计划、任务和声明检查；执行阶段有逐模块结果与行动清单，代码/测试/配置无新增修改，修复状态保持未开始。
