# 视频媒体类型适配与查看器替换规格

## 问题

1. 内容管线只扫描 `jpg/jpeg/png/webp`，`generate-photo-index.ts` 永远产不出 `Video` 项，`Video` 类型、校验和两套主题的视频舞台都在，但站点里没有任何真实视频进入内容索引。
2. 唯一的手工演示视频放在 `public/media/video/`，与「照片原图在 `media-source/<相册目录>/`、构建期派生到 `public/media/<相册目录>/`」的既有分层不一致；`SOURCES.md` 记录的 `video/n.mp4` 与封面 `thumbs/flowers.webp` 都已不存在。
3. `Video.captions` 及 `<track>`、`.vtt` 是上一轮的自定义字幕方案，现在决定下线，不留占位说明。
4. 查看器是两套主题各自手写的 `dialog`（自绘控制条、滚轮切换、移动端滑动、纯黑底、照片模式隐藏关闭按钮、不可见计数器）。用户要求改用 `yet-another-react-lightbox` 的默认交互，并保留会话归属、音乐协调和焦点行为。

## 两个技术判断（先回答，再实施）

### 判断一：视频缩略图（poster）

**结论：不自动抽帧、不因缺封面失败。** 维护者在同一相册目录提供 `<视频同名>.poster.jpg` 作为真实帧时，构建期走现有 WebP 派生管线（内容哈希 + 清单缓存），把 `video.poster` / `video.posterSrcSet` 指向派生资源；没有提供时由构建期渲染一张中立占位封面（16:9 深色底纹，`video-poster-placeholder-v1`，同样派生 480/960/1600 WebP 并进清单缓存），因此视频始终有封面、构建不失败。缩略图上「这是视频」的辨识改由页面按媒体类型在正中叠加主题色圆形 ▶ 标识完成，不烘焙进封面资源。

依据：

- 本机未安装 `ffmpeg`/`ffprobe`；CI 目前只有 Node 24 + `npm ci` + Playwright，自动抽帧必须在 CI 落地额外能力：`apt-get install ffmpeg`（数百 MB 原生依赖、额外安装时间与缓存键），或 WASM 版 ffmpeg npm 包（约 25 MB 依赖、启动与内存成本，仍要维护）。两者都超出「纯静态站点、构建期只用 Node」的既有边界。
- 封面是内容选择，不是机械结果：维护者挑一帧比自动取首帧更可控，也让封面与派生管线保持一致（同样进 480/960/1600/2560 WebP 与缓存，而不是多出一套未压缩的原图发布路径）。
- 本次演示视频的封面用 macOS 自带 `qlmanage -t` 离线抽首帧后转 JPEG，作为**一次性的离线素材准备**记录在 `SOURCES.md`；构建期永不调用它，也不需要 `ffmpeg`。

### 判断二：视频格式转换

**结论：本期不引入转码服务，也不做运行时转码。** 约定发布用 H.264 + AAC 的 MP4（faststart），由维护者离线准备；构建期只做容器/扩展名与体积基线校验，超限直接失败并给出提示。

基线：`media-source/<相册目录>/*.mp4` 之外的视频扩展名（`.mov`、`.webm`、`.mkv`、`.avi`、`.m4v`、`.hevc` 等）在构建期报错并提示离线转码；单个视频 ≤100 MB 为推荐上限（超出打印警告），>200 MB 为硬上限（构建失败）。附加事实：GitHub 普通推送阻止超过 100 MiB 的单文件，因此推荐上限同时是仓库侧的硬约束。PC 浏览器、移动端浏览器与未来 WebView 共用这一种容器，不按端生成不同格式；需要照顾弱网时也是补同一格式的更低码率/分辨率变体，而不是引入 WebM/HEVC 分支。

离线路径（写入 README，不新增任何依赖）：HEVC/体积过大时先转码再入库，例如 `ffmpeg -i in.mov -c:v libx264 -crf 23 -preset medium -c:a aac -b:a 128k -movflags +faststart out.mp4`；`ffmpeg` 只用于维护者本机离线处理，站点构建、CI 与运行时都不需要它。

依赖与自行实现评估（SDD「依赖与自行实现评估」）：

| 能力 | 候选 | 选择与理由 |
| --- | --- | --- |
| 视频封面 | 构建期 ffmpeg 抽帧 / WASM ffmpeg / 维护者提供 `.poster.jpg` | 选维护者提供：零新增依赖，复用现有 WebP 派生与缓存，封面可控、可追溯 |
| 视频转码 | 运行时转码 / 构建期转码 / 离线转码 | 选离线转码：本站是纯静态站，构建期转码会把原生依赖引入 CI，运行时转码需要后端，均越界 |
| 查看器 | 继续维护两套自绘 `dialog` / `yet-another-react-lightbox` | 选库：默认交互（含视频插件、字幕位置、焦点与滚动锁）由库维护，主题只保留包装组件与变量化样式覆盖 |

## 目标

- 相册目录内照片与视频同层维护；构建期把视频按内容哈希发布到 `public/media/<相册目录>/`，并生成 `Video` 内容项。
- 视频封面走派生 WebP，缺失即构建失败；视频扩展名与体积有明确基线。
- 字幕能力整体下线，不留空实现。
- 相册详情页与全部影像页的大图查看/视频播放改用 `yet-another-react-lightbox`，两套主题各自拥有包装组件与样式覆盖。
- SDD 基线（requirements、architecture、module.md、README、ADR）与真实实现一致。

## 非目标

- 不引入后端、数据库、登录、在线 CMS、付费服务、运行时转码。
- 不实现自动幻灯片、视频自动推进、原生桥接。
- 不改动首页两段布局、主回忆队列、路由结构与主题切换规则。
- 首页主回忆仍只允许照片，不接入查看器。

## 行为规格

### 媒体目录与发布

1. 相册目录 `media-source/<YYYY-MM-sequenceNN-相册名>/` 内同时存放照片与视频，不设 `photos`/`video` 中间层。
2. 视频源文件只接受 `.mp4`；其它视频扩展名在构建期报错，提示离线转码为 H.264 + AAC MP4。
3. 视频封面源素材 `<视频同名>.poster.jpg`（同时接受 `.jpeg`/`.png`/`.webp` 后缀）是可选的真实帧：提供了就派生它，没有则由构建期渲染 16:9 中立占位封面；两种情况索引里都写 `poster`/`posterSrcSet`，构建都不会失败。
4. `*.poster.<图片后缀>` 是保留名：不得再被当成照片；没有同名视频的 `*.poster.jpg` 构建失败，避免照片被静默吞掉。
5. 构建期把视频源文件按内容哈希发布为 `public/media/<相册目录>/<文件名>.<哈希12>.mp4`；目标存在即跳过复制，源文件字节不变时不重复拷贝；源视频被删除或改名后旧产物由清单清理。
6. 封面（真实帧或占位封面）与照片一样派生 480/960/1600/2560 宽度 WebP（不放大、内容哈希命名、命中 `.cache/media-variants/` 清单则不重编码）；占位封面的缓存键写在清单 `entries` 的 `${视频源路径}#poster`，占位版本提升即重新生成。
7. 体积基线：单个视频 >200 MB 构建失败；>100 MB 打印警告。校验位置写到具体媒体与字段。
8. `dist` 不含 `media-source`、不含 `.vtt`、不含旧的 `public/media/video/` 残留。

### 内容索引

9. 视频项字段：稳定 `id`（由文件名派生，规则与照片一致）、`type: 'video'`、`src`（相对 public 的 `media/<相册目录>/<文件名>.<哈希12>.mp4`）、必填 `poster`（派生 WebP 最大档，真实帧或占位封面）、`posterSrcSet`、`width`/`height`（取封面派生尺寸；占位封面为 16:9，因此不探测真实视频画幅）。
10. 相册内媒体顺序规则（照片与视频共用一条规则）：`topNN` 文件优先（编号升序），其余按文件名自然序；该顺序是相册详情、留影页层叠封面与后续展示的唯一事实来源，主题不得重新排序。
11. 首页主回忆仍只从 `media-source/home-memory.json` 读取照片，视频不进入主回忆；主回忆的 `src` 必须指向相册目录中的照片。

### 字幕下线

12. 删除 `Video.captions`、两处校验中的字幕引用、查看器里的 `<track>`、`public/media/video/weekend-clip.zh.vtt`、README 与 `SOURCES.md` 中的字幕说明；不保留「暂不支持」占位。

### 查看器（yet-another-react-lightbox）

13. 相册详情页与全部影像页使用共用查看器（`src/media-viewer`，基于 `yet-another-react-lightbox@3.32.2`，启用 Captions/Fullscreen/Slideshow/Thumbnails/Video/Zoom 六个插件）；首页主回忆不接入查看器。安装前核对 peerDependencies：该版本声明 `react: ^16.8.0 || ^17 || ^18 || ^19`，与 React 19.3.0 兼容，安装无 peer 警告。
14. 会话仍由 `src/playback` 唯一持有：查看器受控渲染 `open`/`index`，用户翻页只通过 `on.view` 回写会话索引，查看器不保存第二份索引副本；关闭、路由变化、卸载时释放事件监听、媒体资源与计时任务（视频元素随组件卸载销毁，查看器显式解绑 video 事件）。
15. 视频打开/播放时暂停背景音乐；结束后仅在用户此前开启且未主动关闭时恢复（保留既有 `blockedByVideo` 语义：当前媒体是视频即阻断音乐）。
16. 视频结束停留当前项，不自动推进；幻灯片只能由工具栏按钮显式启动，进入查看器不会自动播放幻灯片。
17. 查看器是**共用组件**：实现放在独立模块 `src/media-viewer`，两套主题只在会话存在时挂载同一个 `MediaViewer`，主题目录内不保留任何查看器实现或样式。查看器样式与功能都不可按主题定制（不得覆盖 `.viewer`/`.yarl__*` 类名、不得增删插件、不得写查看器 CSS），内部键盘焦点环固定为白色。该规则同步写入 requirements、architecture、AGENTS、SDD 指南与 themes/module.md。
18. 插件与外观对齐 `yet-another-react-lightbox` 官方 Full-blown 示例：Captions、Fullscreen、Slideshow、Thumbnails、Video、Zoom 全部启用并沿用库默认样式；幻灯片只能由工具栏按钮显式启动（`autoplay: false`），视频自然结束不会推进队列。
18a. 工具栏只保留幻灯片与全屏：放大、缩小、缩略图开关与关闭按钮在全端都不渲染，退出靠 Esc 与点击黑色背景；上一项/下一项只在桌面（≥1200px）显示。缩略图上方新增与屏幕同宽的自有收起条（`lucide-react` 的 ChevronDown/ChevronUp，收起/展开缩略图带），寄语按影像实际渲染尺寸贴在其左下角。
18b. 全屏只展示影像（其余组件隐藏），且进入/退出全屏后把焦点交回查看器容器：PC 全屏下键盘左右方向键仍可切图，手机与平板在全屏下仍可触摸滑动切图。
19. 保留项：照片寄语仍显示（captions 插件渲染，文案来自 `media.caption` 回退 `description`）；照片 `object-fit: contain` 不裁切；打开时定位到所点击媒体；单张相册不出现无效切换（首尾按钮禁用，`carousel.finite` 关闭循环）；Esc 可关闭、也可用库默认关闭按钮关闭；关闭后焦点回到触发元素；查看器打开期间 Tab 在查看器内部循环（库把其余页面标记 inert，查看器在边界回绕且只统计真正可 Tab 到的控件，否则焦点会落到浏览器 chrome 使 Esc 与方向键失效）。
20. 明确取代（写进需求基线）：不可见数量计数器、照片模式不渲染关闭按钮、纯黑背景定制、桌面滚轮切换、移动端仅滑动、视频独立影院控制条，一律改为该库默认交互；照片与视频在同一舞台内按库默认布局呈现。自定义加载中的提示、加载失败状态面板与重试按钮同样下线，改为库默认的错误图标 + 用户手动切换或关闭后重新打开。
21. 视频项使用视频插件（原生 HTML5 video + `controls`），相册缩略图网格继续显示可辨识的播放标识：由页面按媒体类型在缩略图正中叠加「中间凸起的通透玻璃按钮」（半透明白色磨砂 + 顶部高光与投影）配 `lucide-react` 实心 `Play` 图标、图标固定灰色（桌面 38px、手机 26px），不烘焙进封面资源，也不用字符画充当图标。

## 验收条件

1. 相册页出现视频缩略图，播放标识可辨识；点击进入查看器后可播放、暂停、调进度、（浏览器可用时）全屏，视频结束后停留当前项。
2. 视频与照片来自同一层目录结构；`dist` 中不含 `media-source`、不含 `.vtt`、不含 `public/media/video` 残留。
3. 构建产物里视频 URL 正确：`media/<相册目录>/<文件名>.<哈希>.mp4`，由 `content.mediaUrl()` 统一加 `VITE_MEDIA_BASE_URL` / `BASE_URL` 前缀，GitHub Pages 子路径下可加载。
4. 视频容器/扩展名不符、体积超限、封面候选比例与 `width`/`height` 不符或存在孤儿封面源素材时构建失败，错误指出具体文件与字段位置；缺少封面源素材不再失败，改为构建期生成占位封面。
5. 播放视频时背景音乐暂停，视频结束后按原规则恢复；关闭查看器后无残留音频、视频或计时任务。
6. 共用查看器在两端表现一致（同一模块、同一根类名、同一焦点环），无描边类回归（按钮任何状态无边框、键盘焦点可见、鼠标点击无残留聚焦框）；主题目录内不存在查看器实现或样式。

## 影响模块

`media-viewer`（新增共用查看器模块与命令契约）、`scripts`（生成器与校验、SDD 依赖白名单）、`content`（模型与校验）、`playback`（会话索引契约）、`themes`（挂载共用查看器、相册网格视频缩略图与播放入口）、docs（需求、架构、模块、README、AGENTS、SDD 指南、ADR、SOURCES）。
