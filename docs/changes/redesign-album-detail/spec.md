# 相册详情页沉浸式重构

## 问题

`#/albums/:albumId` 当前只有普通面包屑、标题区、固定 4:3 三列缩略图和“下一本相册”推荐。它无法突出一段相册的情绪，且把手机竖拍、方图与横拍都放进同一比例框，不能按原始比例阅读。无效相册 ID 与当前相册无内容的反馈也没有形成详情页一致的视觉与恢复路径。

## 目标

- 完全以“电影接触表”替换旧详情页：先以沉浸式主题私有开场承载相册信息，再呈现原始比例瀑布流影像墙。
- 开场采用“家庭档案”语气：显示档案标签、标题、相册日期、相册说明、可选开场引言、影像数量与“从第一张开始”入口。
- 在每个相册目录的 `meta.json.album` 中新增可选 `opening`，最多 20 个字符；未填写时详情页使用 `description` 作为开场引言回退。
- 横拍、竖拍、方图、手机 9:16 图片与视频封面均以原始比例显示，不使用 `cover` 裁切；影像点击仍按既有 `onOpen(album, media.id)` 进入唯一 playback 会话。
- 两个主题维持各自 JSX、CSS 和视觉语言，不共享主题 UI 或样式；路由 URL、`Album` 的既有字段语义、媒体队列和 playback 集成契约保持不变。
- 在详情页范围提供明确的图片加载中/失败、空相册、无效相册 ID 与相册内容配置异常状态。

## 非目标

- 不修改首页、留影页、相册索引页或查看器的视觉设计和操作。
- 不新增依赖、业务后端、数据库、登录、内容管理或原生桥接。
- 不修改 Hash 路由结构、媒体 URL 解析规则、`album.media` 排序规则或查看器 session 状态机。
- 不为照片补录宽高字段，不改变现有资源或相册目录命名。
- 不实现自动幻灯片、相册内筛选、排序、编辑、收藏或分享。

## 已确认设计

### 页面层级

1. 顶部提供“返回留影”链接。
2. 沉浸式开场使用主题自己的宽幅背景、遮罩与排版。开场不引用相册照片作为背景，避免不同素材比例或网络失败改变结构；内容包括档案式小标签、`album.title`、日期、`album.description`、`album.opening ?? album.description`、影像数量和首张媒体入口。
3. 开场后以“这一段的影像”作为节标题，使用原始比例瀑布流展示 `album.media`，视频继续有封面和播放标识。
4. 移除旧的固定 4:3 `.photoGrid`、旧详情头和“接下来的影像”区块；不保留旧样式或仅供旧详情页使用的组件分支。

### 原始比例与阅读顺序

- 照片与视频封面均以 `width: 100%; height: auto` 呈现，绝不裁切主体；视频没有 poster 时采用详情页既有的可读占位状态。
- 桌面使用三列 CSS 多栏瀑布流，900px 及以下两列，390px 及以下一列。浏览器以 DOM 中 `album.media` 的构建期顺序生成卡片；Tab 顺序、可访问名称和打开查看器传入的完整播放队列均保持该顺序。多栏仅改变视觉排版，绝不重排 `album.media` 或创建第二份播放状态。
- 当前内容索引不含所有图片尺寸，因此加载前可显示主题私有骨架占位，图片原始尺寸可用后自然确定卡片高度；不伪造 3:2 预留框。
- 每个主题在自己的 `PhotoImage` 中增加仅供该主题使用的自然比例渲染变体，保留普通页面、留影页封面和首页原有的 `cover/contain` 行为。

### 详情页状态与恢复

- 图片加载中：卡片显示尺寸稳定的主题私有骨架和 `aria-busy`；加载成功后替换为原始比例图片。
- 单个图片加载失败：卡片保留在影像流中并显示“影像暂时无法加载”，不导致整页白屏；用户仍可继续其他影像。查看器内已有的重试/切换行为保持不变。
- 空相册：保留沉浸式开场，但影像区显示“这本相册正在整理”，提供返回留影入口；不渲染“从第一张开始”按钮或无效瀑布流。
- 无效 ID：仅当路由为 `#/albums/:id` 且找不到相册时，渲染主题私有的详情页未找到状态，提供返回留影及首页链接。
- 运行时相册内容配置异常：仅在相册详情路由渲染主题私有错误状态，显示现有可定位错误信息和返回首页入口；其他路由维持原有错误处理。

### 内容配置

```json
{
  "album": {
    "description": "会走路了，什么都想摸一摸。",
    "opening": "一岁，是好奇心开始有了方向的年纪。"
  }
}
```

- `opening` 是相册级开场引言，允许省略，必须是字符串；去除首尾空白后不得为空，Unicode 字符计数不得超过 20。
- 构建期生成索引将 `opening` 原样传入 `Album`；运行时 `validateContent` 使用同一规则复核。
- `description` 继续最多 16 个字符，作为相册卡片和缺省开场文案；`opening` 未设置时详情页显示 `description`，若两者都未设置则不渲染引言段落。

## 验收条件

1. `#/albums/2025-05-sequence00` 在海边与草原主题均显示新的沉浸式开场、档案式内容与“这一段的影像”瀑布流；旧固定 4:3 网格、旧详情头和“接下来的影像”不再渲染。
2. 两主题的开场均显示相册标题、日期、影像数量、演示标识、说明，以及 `opening`（缺省时展示 `description`）；“从第一张开始”打开既有查看器的第一项。
3. 横拍、竖拍、方图与视频封面在详情页不使用 `object-fit: cover` 或固定 4:3 容器裁切；桌面三列、900px 及以下两列、390px 及以下一列，无横向溢出。
4. 所有详情页缩略图按构建期 `album.media` 顺序提供可访问名称并调用原有 `onOpen(album, media.id)`；查看器打开定位正确、方向键/Esc 与 playback 队列行为不变。
5. `meta.json.album.opening` 可选，最多 20 个 Unicode 字符，空白、非字符串和超长值使生成脚本失败且错误定位到相册路径；生成内容和运行时校验保留有效值。
6. 无 `opening` 的相册详情开场回退到 `description`；缺少两者时不显示空引言区域。
7. 图片加载中、单图失败、空相册、无效 ID 与相册详情路由的内容配置失败均有可读、可访问且能返回的状态；单图失败不影响打开其他影像。
8. 两主题之间不导入 JSX、CSS 或主题资产；不新增依赖；路由 URL、媒体 URL、相册媒体数据顺序和 playback 状态所有权不变。
9. 删除旧详情页专用 JSX、样式与测试断言，不留下死代码或无效样式选择器。
10. `npm run check`、`npm run build`、`npm run test:e2e` 均通过；使用静态构建产物在桌面和移动浏览器视口核对两主题的目标路由与状态。

## 依赖与实现评估

- 已有实现：主题私有 `PhotoImage` 已提供骨架与失败反馈，`MediaTile` 已保持查看器入口，适合扩展为自然比例详情变体。
- 平台能力：CSS 多栏可直接实现静态原始比例瀑布流，无运行时布局库或尺寸测量调度。
- 备选：CSS Grid 固定比例会裁切或留白；JS 瀑布流库/测量算法增加依赖、加载抖动和视觉/DOM 顺序协调成本；实验性 CSS masonry 兼容性不足。
- 选择：两个主题各自用 CSS 多栏 + 原始比例图片，复用既有图片状态与查看器入口；零新增依赖，接受多栏视觉流按列阅读，但保留 DOM、键盘与播放队列顺序。
