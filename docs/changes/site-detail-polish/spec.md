# 网站整体细节修复

本记录为“网站整体细节修复”长期变更记录。后续细节只追加编号条目或更新其状态，不另建变更目录。

## SD-001 全站默认禁止选择展示文字与图片

### 问题

页面展示文字可以被鼠标拖拽高亮选择，图片也可能被选择或原生拖拽；这些浏览器默认行为会干扰以浏览和触控操作为主的影像网站。

### 目标

- 默认禁止站点展示文字被选择。
- 默认禁止图片被选择及原生拖拽。
- 保留标准可编辑字段中的文字选择能力。

### 非目标

- 不改变页面内容、路由、查看器、媒体加载或主题视觉设计。
- 不为这一规则增加 JavaScript 事件拦截、依赖或主题专属实现。
- 不禁止键盘焦点、链接、按钮、触屏或辅助技术操作。

### 行为与边界

- 规则位于 app 全局基础样式，因此同时适用于海边与草原主题，主题间不共享 JSX、CSS 或资产。
- 页面展示内容默认不可选择；图片同时关闭 WebKit 原生拖拽。
- `input`、`textarea` 与 `[contenteditable="true"]` 显式恢复文本选择，保证需要录入或编辑时可复制、选择与修订。
- 未来若某项展示文本需要选择，必须由该功能以更具体的样式显式声明例外，并在本记录追加条目。

### 验收条件

1. 两套主题的首页、留影页、相册页和查看器中的展示文字拖拽后不出现文字选择高亮。
2. 两套主题中的图片不可被选中，且桌面浏览器拖拽图片时不触发原生图片拖拽。
3. `input`、`textarea` 与 `[contenteditable="true"]` 内文字仍可选择。
4. 按 Tab 键时链接、按钮和对话框仍显示既有焦点环；不新增 JavaScript 事件监听或依赖。

## 实现说明

该条改变了全站展示元素的默认操作反馈，属于用户可见交互语义变化，记录模式为 full。使用 CSS 平台能力即可满足需求；不采用 `selectstart`、`dragstart` 等 JavaScript 事件拦截，避免增加生命周期与辅助功能风险。

## SD-002 留影页返回首页入口

### 问题

`#/browse` 的头图区域没有直接返回首页的入口；访客浏览完留影后需要依赖浏览器返回或其他页面内路径才能回到首页。

### 目标

- 在留影页 hero 的标题“留影”上方提供“← 返回首页”链接。
- 链接跳转至首页 Hash 路由 `#/`。
- 视觉上贴近用户提供的深色头图中的左箭头文字入口，同时保持现有主题风格。

### 非目标

- 不增加常驻顶部导航栏。
- 不改变筛选、年份定位、相册卡或首页两屏行为。
- 不共享海边与草原的 JSX、CSS 或主题资产。

### 行为与边界

- 两套主题各自在其 `BrowsePage` hero 内容层渲染语义链接，链接位于标题上方且不被头图装饰层遮挡。
- 链接使用 `href="#/"`，遵循现有 Hash 路由；不新增路由状态、事件监听或 JavaScript 导航逻辑。
- 链接最小高度为 44px，保留全局键盘焦点环；窄视口下与 hero 既有左右边距对齐，不产生横向溢出。

### 验收条件

1. 海边与草原主题的 `#/browse` 均显示可访问名称为“返回首页”的链接，文本视觉上带左箭头。
2. 链接位于“留影”一级标题上方，且在头图可读区域内。
3. 点击链接后 Hash 变为 `#/` 并显示首页标题。
4. 桌面与 360px 宽视口下，链接可键盘聚焦、点击高度不少于 44px，页面不出现横向溢出。

## 实现说明

用户确认采用 hero 内的左对齐文字链接方案，而非实心按钮或独立常驻导航栏。本条新增页面级导航交互，保持 full 模式。

## SD-003 查看器仅允许显式关闭

### 问题

在相册查看器中，点击图片外空白区域或导航、媒体控件等非关闭区域也可能触发原生 `dialog` 的取消路径，造成查看器意外关闭。

### 目标

- 查看器只可通过右上角“关闭查看器”按钮或 Esc 键关闭。
- 点击图片、图片外空白区域、上一项/下一项和视频控件不得关闭查看器。

### 非目标

- 不改变图片左右切换、移动端横滑、桌面滚轮、视频播放或全屏行为。
- 不改变关闭后的焦点恢复、滚动锁与媒体资源清理。
- 不在主题之间共享查看器 JSX 或 CSS。

### 行为与边界

- 两套主题仍以各自的 `dialog` 与 `ViewerCommands.close()` 实现查看器；右上角按钮继续直接调用关闭命令。
- 文档级 Esc 快捷键继续调用关闭命令；查看器生命周期内以原生 DOM 监听器阻止 `cancel` 的浏览器默认关闭，不再映射为关闭命令，并在卸载时移除监听。
- 空白区域和控件的点击保留其原有语义：空白区域无操作，导航按钮仅切换媒体，视频控件仅控制视频。

### 验收条件

1. 海边、草原主题中，点击查看器图片外空白区域后对话框仍打开，当前媒体位置不变。
2. 点击“上一项”或“下一项”后对话框仍打开，且只按边界规则切换媒体。
3. 右上角“关闭查看器”按钮和 Esc 均能关闭查看器，并恢复既有焦点与滚动行为。
4. 不新增全局事件监听、依赖或第二份查看器状态。

## 实现说明

这是一项查看器关闭语义修复，属于 full。Esc 已由文档级键盘监听显式处理；原生 `cancel` 需用 DOM 监听器阻止默认行为，避免浏览器的非显式取消路径绕过已确认的关闭入口。监听器的创建和清理由各主题查看器组件拥有。

### SD-003 更正：背景点击关闭

前述“图片外空白区域不得关闭”的记录来自对用户陈述的错误理解，现由用户明确更正：点击查看器黑色背景必须关闭。该更正覆盖本条此前与背景点击相关的目标、行为、验收条件和实现说明；图片、导航按钮与媒体控件仍不关闭。

#### 更正后的验收条件

1. 海边、草原主题中，点击图片外的黑色背景后对话框关闭。
2. 点击图片后对话框保持打开且当前媒体位置不变。
3. 点击上一项或下一项后对话框保持打开且只按边界规则切换媒体。
4. 关闭图标、Esc 和黑色背景点击均能关闭；视频媒体与其控件保持其自身交互而不关闭。

## SD-004 缩略图卡片移除红色外焦点框

### 问题

相册详情中的可点击缩略图是 `button`，键盘焦点状态继承全局红色外描边，视觉上像图片外多出一圈红框。

### 目标

- 移除所有主题缩略图卡片的外侧红色焦点框与图片内部焦点描边。
- 保留缩略图的键盘可聚焦与 Enter/Space 打开能力。

### 非目标

- 不改变缩略图点击、查看器打开、键盘导航或全局其他控件的焦点环。
- 不修改图片资源、布局、主题 Token 或跨主题共享方式。

### 行为与边界

- 海边与草原主题各自在自己的 `ThemePages.module.css` 覆盖 `.mediaTile` 的焦点 outline。
- 缩略图聚焦时不显示外侧或图片内部描边；该局部视觉例外不改变卡片可聚焦与激活语义。

### 验收条件

1. 两套主题的相册详情缩略图获得键盘焦点时，按钮本身不出现外侧红框。
2. 缩略图图片内部不显示任何焦点描边。
3. 鼠标点击、键盘 Enter/Space 打开查看器的行为不变。

## SD-005 移动端留影页顶部固定

移动端（≤600px）留影页的 hero、返回首页、类型筛选和年份导航固定在视口顶部；相册列表在其下方滚动。海边与草原分别实现，桌面与平板布局不变。

验收：360px 视口滚动相册列表后，hero、筛选和年份导航仍在顶部且列表首项不被遮挡；筛选、年份定位、返回首页均可用，无横向溢出。

补充：年份增加后，移动端年份导航保持单行；年份标签与按钮缩小，且不遮挡列表。

补充：手机与平板（≤900px）年份导航统一单行横向滚动，隐藏滚动条但保留触摸/触控板横向滑动；桌面保留左侧定位栏。

补充：横向滚动时“年份”标签固定在左侧，只有年份按钮移动。

更正：标签不得以 sticky 叠在按钮上，也不得有单独背景色；“年份”作为滚动区外的固定、透明标签，年份按钮独立横向滚动。

更正：手机端固定年份导航的**整个容器**必须使用不透明页面底色，遮住下方滚动的相册卡片；仅“年份”文字不得单独形成背景块。

更正：遮罩色必须与各主题实际相册列表的应用壳层底色相同，不得使用不匹配的 `canvas` token；遮罩从 hero 底部起连续覆盖至年份按钮行，不能留下卡片可穿透的间隙。

更正：年份遮罩必须在筛选胶囊之下；筛选胶囊完整显示在遮罩之上，遮罩只阻挡其下方的滚动列表。

### SD-005 补充：手机年份定位偏移

手机端点击年份按钮后，目标年份标题必须出现在完整固定操作区（hero、筛选、年份导航）下方，不能被遮挡而误显为后续年份；桌面与平板的定位行为不变。

## SD-009 首页主回忆手动换图重置自动轮播

### 问题

自动轮播采用固定周期。用户在周期末尾手动切换图片后，旧周期仍会很快触发下一次自动切换，导致新图片几乎无法停留。

### 目标与边界

- 每次实际手动换图后，自动轮播从完整的 2 秒周期重新计时。
- 覆盖左右按钮、第二屏横向触控板输入、触屏横滑与桌面拖动；自动轮播自身保持每 2 秒一次。
- 暂停、悬停、失焦、查看器打开或不可见页面时不启动计时器；手动换图也不强行恢复已暂停的自动播放。
- 两套主题继续各自维护 UI，仅复用 albums 的无 UI 计时器契约。

### 验收条件

1. 自动轮播运行中手动换图，旧计时器被清理并开始一条新的完整周期。
2. 自动轮播未运行时手动换图不创建新的计时器。
3. 海边、草原主题的所有手动换图入口均使用同一重置逻辑。

## SD-010 手机与平板查看器隐藏切换按钮

手机与平板宽度（≤900px）的相册查看器不显示“上一项”“下一项”按钮，统一以横向滑动切换；桌面保留按钮。该规则按视口宽度生效，不依赖浏览器是否报告 coarse pointer。

补充：手机与平板查看器的照片舞台使用全部可用横向宽度，同时保留图片原始比例与 `contain` 高度约束，不拉伸或裁切。

补充：≤900px 查看器移除外层仅为桌面控制保留的横向内边距，使图片舞台延伸至查看器边缘。

更正：上述查看器平板规则覆盖至 1199px，以包含 1024px iPad；1200px 起才采用桌面按钮与留白布局。

更正：手机 ≤600px 的紧凑规则同样不得重新加入横向内边距，只保留上下安全区。

更正：触摸设备的照片舞台不再保留 10px 横向内边距，图片使用查看器全部横向宽度。

## SD-011 照片查看模式移除关闭按钮

### 问题

查看器右上角的圆形关闭按钮在照片查看模式下属于多余控件：照片是静默舞台，用户已在更早条目中确认黑色背景点击即可关闭。手机、平板、桌面三端都要求去掉该按钮。

### 目标

- 照片查看模式不再渲染“关闭查看器”按钮，覆盖手机、平板、桌面三种宽度。
- 退出照片查看仍保留既有入口：点击黑色背景、Esc。
- 视频与“这里暂时没有影像”空状态继续保留显式关闭按钮。

### 非目标

- 不改变图片切换、横滑、滚轮、全屏、焦点恢复与滚动锁行为。
- 不改变视频控件，也不在主题之间共享查看器 JSX 或 CSS。

### 行为与边界

- 两套主题各自在查看器内容层按当前媒体类型决定是否渲染关闭按钮：仅当当前项不是照片时渲染。
- 移除按钮后，手机与平板的照片模式在查看器内不再有可聚焦控件，因此 Tab 必须被就地保留在查看器上，不能移动到模态框后面的页面内容。
- 照片加载失败时仍可通过背景点击或 Esc 退出；重试按钮保持可用。

### 验收条件

1. 海边、草原主题在 360px、1024px、1440px 三种宽度下打开照片，查看器内“关闭查看器”按钮数量为 0。
2. 同一条件下 Esc 与黑色背景点击均能关闭查看器，并回到相册详情。
3. 手机宽度下连续按 Tab，焦点始终留在查看器内。
4. 视频与空状态仍渲染可访问名称为“关闭查看器”的按钮。

## SD-012 手机与平板相册详情压缩首幅并缩小图集

### 问题

相册详情页在手机与平板上首幅过高，图集照片又过大：≤390px 时图集被压成单列，一张照片几乎占满整屏，首屏只能看到约两张，浏览成本高。

### 目标

- 手机与平板的首幅高度降到当前值的三分之二（手机 420px → 280px；平板 500px → 333px 上限）。
- 首幅内的标题、副标题、引言与返回入口字号同步缩小，缩小后内容不得被裁切。
- 图集照片缩小：手机双列、平板（含 1024px iPad）三列，首屏至少完整看到 4 张照片。
- 照片继续按原始比例显示，不裁切、不拉伸。
- 桌面（≥1200px）布局与字号保持不变。

### 非目标

- 不改变查看器、留影列表页、相册卡片或其他页面。
- 不改变相册数据、排序或图片资源。

### 行为与边界

- 首幅用 `min-height` 表达三分之二，内容更高时允许自然撑高，因此不产生裁切。
- 图集列数只按视口宽度切换，触摸与鼠标设备一致。

### 验收条件

1. 390×844 下首幅高度 ≤281px，820×1180 与 1024×768 下 ≤334px，1440×900 桌面保持 450px。
2. 三个窄视口下首幅引言底部不超过首幅下边界（无裁切）。
3. 390×844 图集为 2 列，820×1180 与 1024×768 为 3 列。
4. 手机与平板的图集首屏至少完整显示 4 张照片，且标题字号小于桌面。
5. 海边与草原两套主题结果一致。

### SD-012 更正：再降 1/5、手机三列、去掉缩略图容器底色

- 手机与平板的横幅高度、标题/副标题/引言/返回入口字号在当前基础上再降五分之一（手机首幅 280→224px、平板上限 333→266px）。
- 手机图集由两列改为三列。
- 详情页缩略图容器不再用 `min-height: 150px` 撑高：容器高度必须等于图片高度，图片加载完成后不得露出容器底色形成空白块。

#### 追加验收条件

6. 手机 390×844 首幅 ≤225px、平板 820×1180 首幅 ≤267px，引言底部不超过首幅下边界。
7. 手机与平板图集均为 3 列，首屏至少完整显示 4 张。
8. 手机与平板每个缩略图容器高度与图片高度差不大于 1px。

## SD-007 扩展假相册数据用于滑动验证

新增 2026–2029 四个假相册目录，每册包含 2–3 张复用的假图片和简短文案，用正常构建期索引验证多年份移动端滚动；不改变真实数据模型或展示逻辑。

## SD-008 手机主题切换按钮固定

### 问题

手机浏览留影页时，页面顶部的主题切换按钮会随内容上滑而离开视口。

### 目标与边界

- 仅在手机宽度（≤600px）固定主题切换按钮，使其保持在既有右侧安全区位置。
- PC 与平板（>600px）继续随所属页面内容滚动。
- 不改变按钮的主题切换功能、视觉、尺寸、音乐控制或查看器行为。

### 验收条件

1. 两套主题在 360px 视口的留影页滚动后，主题切换按钮仍在视口内且保持右上位置。
2. 601px 及以上视口中，主题切换按钮不是 fixed/sticky，继续随页面滚动。
3. 主题切换可用，查看器仍不显示主题切换按钮。

更正：固定范围仅为手机端 `#/browse`；手机相册详情页及其余路由仍随内容滚动。

## SD-013 手机端隐藏返回入口并重新居中 hero 文案

### 问题

手机端留影页的“返回首页”和相册详情页的“返回留影”占用 hero 高度；这两个入口在手机上的价值有限，返回可用浏览器返回手势完成。

### 目标

- 手机（≤600px）不展示留影页“返回首页”与相册详情“返回留影”入口。
- 平板与桌面继续展示这两个入口，保持 44px 命中区、原有跳转与焦点环。
- 隐藏入口后重新调整 hero 文案位置，使其在剩余可用高度内居中，避免顶部贴边或底部留出大片空白。

### 非目标

- 不改变类型筛选、年份导航、图集列数与首幅高度。
- 不新增替代性返回控件、路由状态或全局导航。

### 行为与边界

- 两个入口在手机端以 `display: none` 移除，因此不进入 tab 顺序与辅助技术树；返回依赖浏览器返回手势。
- 手机端留影页 hero 文案顶部偏移 46px，详情页首幅文案顶部偏移 36px；桌面与平板沿用原值。
- 两套主题各自在其私有 CSS 中实现，不共享 JSX 或 CSS。

### 验收条件

1. 360×800 与 390×844 下，留影页“返回首页”与详情页“返回留影”均不可见。
2. 820×1180 与 1440×900 下两者均可见，命中区不小于 44px，`href` 分别为 `#/` 与 `#/browse`。
3. 手机端详情页首幅文案完整位于首幅内（上下均不越界），页面无横向溢出。

## SD-014 手机端留影页相册卡片只渲染相册名

### 问题

手机端留影页的相册卡片说明条同时渲染相册名与相册说明，且深色底框铺满卡片宽度。标题与说明挤在一行，长说明被截断，视觉重心落在被省略的文本上。

### 目标

- 手机（≤600px）的相册卡片说明条只渲染相册名，不再渲染相册说明。
- 深色底框贴合文字长度，不再铺满卡片宽度；去掉相册名后的分隔线及其占位。
- 平板与桌面保持“相册名 + 相册说明”的紧凑单行说明条不变。

### 非目标

- 不改变相册封面三层错位结构、封面裁切、卡片点击区域与跳转目标。
- 不改变相册详情页图集说明条与查看器寄语。

### 行为与边界

- 说明条在手机端改为 `width: fit-content` 并取消右侧对齐，宽度上限仍受卡片宽度约束；相册名过长时仍按省略号截断。
- 相册说明在手机端以 `display: none` 隐藏，不进入布局与辅助技术树。
- 两套主题各自在其私有 CSS 的 ≤600px 块实现，不共享样式。

### 验收条件

1. 360px 与 390px 下，海边与草原主题的相册卡片说明部分不可见，相册名可见。
2. 手机端说明条宽度大于等于相册名宽度、且小于卡片宽度，差值仅为左右内边距；相册名无右侧分隔线且不透明度为 1。
3. 820px 与 1440px 下仍同时显示相册名与相册说明。
