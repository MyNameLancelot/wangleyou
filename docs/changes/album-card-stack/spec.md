# 相册卡片层叠封面与相册级元信息

## 问题

- 相册目录的 `meta.json` 以照片文件名为键，只能表达单张照片的元信息，无法表达相册自己的标题、日期和说明。
- 构建期索引从不生成 `album.date` / `album.description`，相册卡片取不到数据：日期固定显示“待续”，描述为空，卡片无法说明这是哪一段日子。
- 相册卡片只用单张封面，看不出一个相册里其实有多张照片。

## 目标

- `meta.json` 只保留“相册级元信息”：`album` 段描述目录本身，照片顺序与照片 ID 由构建期脚本按文件名生成。
- 相册卡片用最多三张照片向右上错位层叠：第一张完整显示在左下，第 2、3 张各向右上错开，只露出上侧与右侧边缘。
- 相册卡片显示真实的相册日期与说明，不再出现“待续”。

## 非目标

- 不改相册详情页的布局、网格和“从这里播放”。
- 不改首页、留影页、媒体查看器、路由与媒体 URL 解析。
- 不引入运行时目录扫描、后台、上传或在线内容管理。

## 行为与边界

- `meta.json` 结构：`{ "album": { "title"?, "description"?, "date"? } }`；出现 `album` 以外的键构建期报错，照片不写进配置。
- `album.description` 只显示在卡片的一行里，因此限制在 16 个字符以内（含标点），超过时构建期报错并给出当前字数。
- 目录名仍必须是 `YYYY-MM-sequenceNN-相册名`；`album.title` 缺省取目录名后缀，`album.date` 缺省取目录名的年月（允许只写到月，也可写完整日期）。
- 照片顺序由构建期决定：`topNN` 文件名优先（按 N 升序），其余按文件名自然序；照片 ID 由文件名生成，同相册内必须唯一。
- 层叠数量取可用照片数：0 张显示原有空状态，1 张就是整张封面，2–3 张按层叠显示，超过 3 张只取前三张。
- 悬浮时层间错位略微张开，减少动态模式下不产生位移；卡片命中区、可访问名称与数量角标保持不变。
- 移动端 360px 单列时层叠仍成立且不产生横向溢出。

## 验收条件

1. `meta.json` 只包含 `album` 段；三个现有相册的配置完成迁移，`npm run check` 与 `npm run build` 通过。
2. 构建期遇到 `album` 以外的键时失败并给出字段位置；照片不逐张登记，顺序与 ID 均为构建期生成。
3. `album.description` 超过 16 个字符时构建失败并报告当前字数；三个现有相册的说明都在 16 字以内且与相册主题一致（出生、百日、周岁）。
4. 相册卡片日期显示真实日期（当前三个相册为 2025.05 / 2024.08 / 2024.05），不再出现“待续”。
5. 相册卡片显示 `album.description`；未配置说明的相册不渲染空描述行。
6. 相册卡片渲染不超过三层层叠，第一张照片完整可见，第 2、3 张分别向右上错位 12px、24px（三层时），仅露出上侧和右侧边缘。
7. 三张以上照片的相册只层叠前三张；两张照片的相册只层叠两层；单张照片的相册封面铺满卡片区域。
8. 悬浮时层间错位增大且过渡平滑；`prefers-reduced-motion: reduce` 下不产生位移动画。
9. 相册卡片的可访问名称仍为“查看相册：<标题>”，数量角标仍显示照片数量。
10. 360px 视口下相册页单列显示，卡片不横向溢出。
11. 留影页按年份列出相册（每个相册一张卡），同一年内按目录月份与序列排列；相册详情页仍列该相册的照片。

## 实现说明

相册配置结构与相册卡片呈现同时变化，因此按 full 记录。两个主题各自实现自己的卡片层叠样式，不共享 JSX 或 CSS；排序与回退规则集中在构建期索引脚本，UI 不重复推断。
