# 相册卡片层叠封面与相册级元信息

## 问题

- 相册目录的 `meta.json` 以照片文件名为键，只能表达单张照片的元信息，无法表达相册自己的标题、日期和说明。
- 构建期索引从不生成 `album.date` / `album.description`，相册卡片取不到数据：日期固定显示“待续”，描述为空，卡片无法说明这是哪一段日子。
- 相册卡片只用单张封面，看不出一个相册里其实有多张照片。

## 目标

- `meta.json` 改成“相册级元信息 + 照片数组”两层结构：`album` 描述目录本身，`photos` 数组描述每一张照片。
- 相册卡片用最多三张照片向右上错位层叠：第一张完整显示在左下，第 2、3 张各向右上错开，只露出上侧与右侧边缘。
- 相册卡片显示真实的相册日期与说明，不再出现“待续”。

## 非目标

- 不改相册详情页的布局、网格和“从这里播放”。
- 不改首页、留影页、媒体查看器、路由与媒体 URL 解析。
- 不引入运行时目录扫描、后台、上传或在线内容管理。

## 行为与边界

- `meta.json` 结构：`{ "album": { "title"?, "description"?, "date"? }, "photos": [ { "file", "id", "date"?, "description"?, "alt"?, "width"?, "height"? }, … ] }`。
- 目录名仍必须是 `YYYY-MM-sequenceNN-相册名`；`album.title` 缺省取目录名后缀，`album.date` 缺省取该相册最早的照片日期。
- 照片顺序：`topNN` 文件名优先（按 N 升序），其余按 `photos` 数组顺序。
- `photos` 必须覆盖目录内所有图片文件，且每个条目必须在磁盘上存在；重复引用、缺文件、缺元信息、旧的文件名键结构都在构建期报错并指出位置。
- 层叠数量取可用照片数：0 张显示原有空状态，1 张就是整张封面，2–3 张按层叠显示，超过 3 张只取前三张。
- 悬浮时层间错位略微张开，减少动态模式下不产生位移；卡片命中区、可访问名称与数量角标保持不变。
- 移动端 360px 单列时层叠仍成立且不产生横向溢出。

## 验收条件

1. `meta.json` 使用 `{album, photos}` 结构；三个现有相册的配置完成迁移，`npm run check` 与 `npm run build` 通过。
2. 构建期遇到缺少对应文件的照片条目、未被 `photos` 覆盖的图片文件、重复文件引用或旧的“文件名: 元信息”结构时失败并给出字段位置。
3. 相册卡片日期显示真实日期（当前三个相册为 2025.05.23 / 2024.08.09 / 2024.05.01），不再出现“待续”。
4. 相册卡片显示 `album.description`；未配置说明的相册不渲染空描述行。
5. 相册卡片渲染不超过三层层叠，第一张照片完整可见，第 2、3 张分别向右上错位 12px、24px（三层时），仅露出上侧和右侧边缘。
6. 三张以上照片的相册只层叠前三张；两张照片的相册只层叠两层；单张照片的相册封面铺满卡片区域。
7. 悬浮时层间错位增大且过渡平滑；`prefers-reduced-motion: reduce` 下不产生位移动画。
8. 相册卡片的可访问名称仍为“查看相册：<标题>”，数量角标仍显示照片数量。
9. 360px 视口下相册页单列显示，卡片不横向溢出。
10. 留影页、相册详情页、首页主回忆与查看器行为不变。

## 实现说明

相册配置结构与相册卡片呈现同时变化，因此按 full 记录。两个主题各自实现自己的卡片层叠样式，不共享 JSX 或 CSS；排序与回退规则集中在构建期索引脚本，UI 不重复推断。
