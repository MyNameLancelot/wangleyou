# Android 视频开屏规格

## 问题与目标

用户选定 `.private/generated-video/album-opening-vertical-1080p.mp4` 作为 Android App 开屏。现有原生 View 翻书画面与最终视觉不一致；需在离线安装包内提供视频，开屏不依赖网络下载。

## 范围与行为

- Android 冷启动背景沿用奶油白；加载层使用选定的 1080×1920、约 5.2 秒、无音轨 MP4，按中心裁切铺满竖屏，主体相册保持可见。
- 视频资源归 Android `res/raw`。正常播放从视频首帧到尾帧均使用同一个 `TextureView` 画面层，以一致的中心裁切铺满屏幕；不使用首尾静帧图片，避免裁切和缩放闪动。视频准备前保持奶油白背景；播放失败、主框架错误或系统关闭动画时也回退到奶油白背景及文字说明。
- 每次主页面重新加载从头播放。网页先就绪时，保持加载层直到视频播完；此期间显示“跳过”，点击立即淡出。视频先结束时由同一纹理层停在尾帧等待网页。播放失败时显示奶油白加载背景，不阻塞网页进入。
- 主框架加载失败时停止视频，显示奶油白背景、错误说明和重新连接按钮；重试重新播放。Activity 后台暂停、前台恢复，销毁时释放播放器与回调。
- 冷启动时开屏层已经开始播放，首次主框架 `onPageStarted` 只确认加载状态，不重复初始化播放器；后续重新加载才从视频开头播放，避免首次安装时启动约 1 秒发生闪屏与重播。
- “正在打开回忆”下方显示细轨道和往返移动的短光条，加载期间持续运动；进入页面、报错、后台和销毁时停止，系统关闭动画时保持静态。
- 保持既有站点 URL、WebView、系统状态栏、桌面图标及网页行为。Android 版本升为 1.0.9（versionCode 10），生成本机家庭签名 Release APK。

## 验收

- A1：APK 内含指定视频，视频解码尺寸为 1080×1920；正常播放全程由同一视频画面层中心裁切铺满，首尾不切换图片、无缩放跳变、黑边或可见水印。
- A2：冷启动从首帧开始播放一次；网页先就绪时完整播放后淡出，跳过可立即进入；网页较慢时尾帧保持稳定。
- A3：播放失败、系统关闭动画、断网错误与重试均有奶油白背景和可读文字，不卡在黑屏。
- A4：Activity 后台/销毁释放或暂停视频，返回后可继续；既有状态栏和网页导航不受影响。
- A5：Debug 与家庭签名 Release APK 构建成功，Release 签名校验通过；模拟器验证与真机未验证范围分别记录。
- A6：加载提示下方有清楚但克制的往返动效；退出加载、报错、后台或销毁后不再运行，系统关闭动画时为静态。
- A7：首次主框架开始加载不会重置已启动的本地视频；后续重试或重新加载仍从首帧播放。
