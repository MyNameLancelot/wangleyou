# 0005：构建期媒体派生与响应式瀑布流

日期：2026-09-23。状态：采纳。

## 背景与决定

原图直接发布增加移动端流量，固定比例网格裁切横竖图。采用“仓库源素材 → 增量构建派生 → 静态发布”，用成熟图库库处理原始比例和响应式尺寸。

- 照片、MP4、同名可选封面源图与 meta 在 `media-source/<相册目录>/` 同层维护，首页队列单独位于 `media-source/home-memory.json`。源素材提交 Git，派生媒体不提交。
- sharp 按内容哈希、编码及布局版本生成多尺寸 WebP，保留比例、不放大、清 EXIF；不足预设最小宽度时采用实际源宽，尺寸按编码结果记录，仅容许像素舍入误差。发布文件带哈希，缓存清单先校验结构/版本、安全路径和真实尺寸，未知结构重新派生；内存扫描不提前写原图索引，全部派生/校验成功后暂存并提交缓存和索引，提交失败恢复旧缓存，提交成功后才删除旧媒体。每项输出通过独占临时文件和 rename 避免改写源 inode；本地/CI 同一管线，缓存缺失时完整重建。
- 视频离线准备为 H.264 + AAC、faststart 的 MP4，构建只校验扩展名/体积并按哈希复制，不解码、抽帧或转码。可选真实封面走照片派生；缺失时由 sharp 渲染版本化 16:9 占位封面，始终生成 poster、响应式候选和尺寸。
- 详情使用 `react-photo-album` 的 Masonry，默认计算列数/间距/sizes；相纸留白通过 `padding` 纳入列宽，不通过 border 改变布局。具体尺寸与视觉验收由 [需求](../requirements.md) 维护。

## 候选与取舍

| 候选 | 取舍 |
| --- | --- |
| 原图直发 + 懒加载 | 实现最省，但仍下载大图且不能选择合适尺寸 |
| 图片 CDN / 运行时转码 | 需要站外服务或后端，超出当前边界 |
| 自研 CSS 多栏图库 | 少一个依赖，但需长期处理列高平衡、响应式和 sizes；采用成熟库 |
| 构建期 ffmpeg / WASM 抽帧转码 | 增加依赖、构建时长和故障面；离线准备视频，sharp 占位封面兜底 |

保留源素材增加克隆体积，换取可追溯和重新派生能力。派生不入 Git 意味着部署必须运行生成器，不能用仅读取 Git 文件的 CDN 提供发布媒体。缓存版本须包含输出布局和候选规则；当前编码 profile v3 使旧照片候选重新派生，清单 version 2 保持兼容。源字节变化后在成功发布后清理旧哈希文件。原样直写索引无法保留失败前的有效发布状态，因此选择局部扫描/派生/提交分离，不引入数据库或通用事务框架；两个文件不是跨进程崩溃事务，异常中断后可从只读源重建。

占位封面不能代表真实画幅；准确画面/比例依赖维护者提供真实帧。MP4 编码形态由离线流程保证，当前构建不探测编解码器，扩展名通过不等于编码兼容。

## 影响与验证

影响 scripts 的生成/缓存/校验、content 的尺寸/srcSet 契约、themes 的图库与工作流缓存。验证哈希命中、单文件失效、旧产物清理、原素材不变、缺封面兜底、比例/体积边界及静态子路径。操作步骤见 [README](../../README.md)，实现组织见 [总架构](../architecture.md)。
