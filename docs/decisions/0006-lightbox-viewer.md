# ADR 0006：查看器改用 yet-another-react-lightbox，主题各自包装

日期：2026-09-23
状态：已采纳

## 背景

查看器此前是两套主题各自手写的 `dialog`：自定义图片舞台与视频影院控制条、桌面滚轮切换、移动端仅滑动、照片模式不渲染关闭按钮、纯黑背景定制、不可见数量计数器。用户确认这些定制一律回到库默认交互，并要求查看器继续由 `src/playback` 唯一持有会话，保留音乐协调、焦点回归、主题隔离与「照片寄语仍显示、照片不裁切、打开定位到所点击媒体、单张相册无无效切换」。

## 决策

1. 采用 `yet-another-react-lightbox@3.32.2`（MIT）与 video、captions 插件。选择依据：安装前核对该版本 `peerDependencies` 为 `react: ^16.8.0 || ^17 || ^18 || ^19`、`@types/react: ^16 || ^17 || ^18 || ^19`，与项目的 React 19.3.0 兼容，`npm install` 无 peer 警告，不需要压过 peer 依赖。该包为纯 ESM、无运行时依赖（`dist/index.js` 76.7 KB，video 插件 8.6 KB，captions 插件 5.4 KB）；本次构建产物为 JS 358.18 KB → gzip 109.31 KB、CSS 80.88 KB → gzip 15.69 KB，同一变更同时删除了两份手写查看器，净增量未单独度量。
2. 查看器做成**共用组件**：`src/media-viewer` 模块导出 `MediaViewer` 与 `MediaViewerCommands`，两套主题只在会话存在时挂载同一个组件，不在主题目录里保留任何查看器实现或样式。查看器的类名、样式与功能由该模块与库默认值决定，主题不得覆盖 `.viewer`/`.yarl__*` 类名、不得增删插件、不得写入自己的查看器 CSS；查看器内的键盘焦点环固定为白色，也不随主题变化。所需样式只有 `media-viewer` 模块自己的 CSS（继承站点字体 + 固定焦点环），不引用主题变量。
3. 会话仍由 `playback` 唯一持有：包装受控渲染 `open`/`index`，库的 `view` 事件通过主题合同里的 `stepTo` 命令（`playback.stepSessionTo`）回写会话索引，查看器不保存第二份索引副本；视频事件（play/pause/waiting/timeupdate/ended/error）只翻译成 playback 命令。
4. 插件集合对齐官方 Full-blown 示例：Captions、Fullscreen、Slideshow、Thumbnails、Video、Zoom 全部启用并沿用库默认样式；幻灯片只能由工具栏按钮显式启动（`autoplay: false`），视频自然结束不推进队列。工具栏只保留幻灯片与全屏（放大、缩小、缩略图开关与关闭在全端都不渲染，退出靠 Esc 与背景点击）；上一项/下一项只在桌面显示；缩略图带上方另加一条与屏幕同宽的自有收起条（`lucide-react` 的 ChevronDown/ChevronUp）；寄语按影像实际渲染尺寸贴在其左下角；全屏只展示影像，并把焦点交回查看器容器以保证全屏下键盘与触摸仍能切图。
5. 保留项：视频打开/播放时暂停背景音乐（`blockedByVideo` 语义）、视频结束停留当前项、照片寄语显示、照片 `object-fit: contain` 不裁切、打开定位所点击媒体、关闭后焦点回到触发元素、关闭/路由变化/卸载时释放事件与媒体资源。另保留一条键盘契约：查看器打开期间 Tab 在查看器内部循环（否则焦点越过末位控件会落到浏览器 chrome，Esc 与方向键随之失效）；只有真正可 Tab 到的控件参与回绕，隐藏的缩略图占位项必须排除。
6. 明确取代：不可见数量计数器（改为库默认工具栏，未启用计数器插件）、照片模式不渲染关闭按钮、纯黑背景定制（沿用库默认纯黑底）、桌面滚轮切换、移动端仅滑动、视频独立影院控制条、自定义加载失败/重试面板。`carousel.finite` 与 `controller.closeOnBackdropClick` 保持非循环与黑色背景点击退出。
7. 相册缩略图的视频播放标识由页面按媒体类型叠加（中间凸起的通透玻璃圆钮 + `lucide-react` 实心 Play 图标，图标灰色，居中，桌面 38px、手机 26px，不支持背景模糊时回退为更不透明的白底），不烘焙进封面资源：真实封面与构建期占位封面共用同一套标识，封面资源保持干净、可复用为留影页层叠封面。

## 备选方案

- 继续维护两套手写 `dialog`：完全可控，但所有无障碍、手势、视频控制与焦点细节都要自己实现并长期跟进浏览器行为，用户已明确要求改用库默认交互。
- 两套主题各写一份包装与样式覆盖：与「查看器是共用组件、主题不可定制」的最终要求冲突（会出现样式漂移与两份需要同步维护的实现），因此改为单一共用模块。
- 自行实现焦点陷阱（focus trap）库或额外依赖：库已把其余页面标记 inert，主题包装只需在 Tab 边界回绕，额外依赖不划算。

## 取舍

- 采用库默认交互意味着部分既有定制（滚轮切换、移动端只滑动、照片模式无关闭按钮、隐藏计数器）不再保留，需要同步更新需求基线，避免文档与新行为冲突。
- 共用查看器意味着主题失去查看器外观的自主权（这是用户明确要求：查看器共用、样式与功能都不可定制），换取一致的无障碍/手势/插件行为与单点维护；主题仍然完全拥有页面、卡片与按钮的视觉。
- 库的 DOM 结构与 CSS 类名是外部契约：主题样式覆盖与 e2e 断言都依赖 `.yarl__*` 类名，升级版本时需要重新核对。
- 默认不循环（`carousel.finite: true`）与背景点击关闭不是库默认值，而是为保留既有验收行为显式开启的选项。

## 影响模块

`media-viewer`（新增共用查看器模块与命令契约）、`themes`（挂载共用查看器、相册网格视频缩略图）、`playback`（`stepSessionTo`）、`app`（命令装配）、`scripts`（SDD 依赖白名单新增 themes → media-viewer；e2e 静态服务的 `.mp4` MIME 与 Range 支持）、docs（需求、架构、模块、README、AGENTS/SDD 指南）。
