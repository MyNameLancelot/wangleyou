# 0002：分层设计变量与共享组件治理

日期：2026-09-16  
状态：已被 [0003](0003-retire-penpot-design-governance.md) 替代

## 背景

项目将扩展视频、连续播放、多主题、更多页面和未来 WebView。现有默认主题已经使用 CSS 变量，但 SDD 未明确设计影响，Penpot 中的双主题设计也尚未形成长期可维护的原生变量、组件实例和版本治理。

## 备选方案

### 每个主题复制页面和组件

视觉自由度最高，但同一交互会产生多套组件和状态，修复需要重复同步，容易导致主题行为不一致，不适合长期扩展。

### 仅使用一层 CSS 变量

实现简单，适合当前默认主题；但原始色、业务语义和组件契约混在同一层后，新增主题容易直接依赖颜色名称，媒体查看器等复杂组件也缺少稳定边界。

### 分层 Token、主题模式和共享组件

Primitive 保存原始值，Semantic 保存跨主题业务含义，Component 只表达确有独立契约的组件值；主题映射相同语义，页面复用共享组件实例。前期治理成本较高，但主题、平台和组件规模扩大后维护成本最低。

## 决定

采用第三种方案。

Penpot 维护 Primitive → Semantic → Component 三层原生变量和 Default、Beach、Grassland 模式。运行时 themes 模块只公开对应的语义 CSS 自定义属性；业务模块不得消费主题专属 Primitive，也不得为主题复制业务组件树。

组件按 Core、Media 和 Pattern 分区。变体仅在尺寸、状态、密度、方向或平台确实改变契约时建立。主题差异通过 Token、背景层、主题资产和装饰 Slot 表达，不改变主要控件位置和操作含义。

SDD 使用 `designImpact: none | sync | update`：更新设计基线的变更必须使用 full，并在实现前完成 Penpot 设计；复用既有设计的变化在实现后核对；无用户可见影响的变化不要求操作 Penpot。

## 取舍

- 增加了设计资产治理、迁移和验证成本。
- 原生组件和变量需要避免无意义的变体组合，否则资产库仍会膨胀。
- Penpot、产品需求和架构文档分别承担不同事实来源，维护时需要同步但不得互相复制全文。
- 收益是新增主题无需复制业务组件，组件修复可传播到页面实例，设计和 React 契约可以稳定映射。

## 影响

- SDD 变更声明新增设计影响字段和自动校验。
- Penpot 文件升级为长期设计系统，保留主题、组件、原型和 Changelog。
- themes 模块未来按语义 Token 实现多主题；本决策本身不代表多主题运行时已经完成。
- playback 继续唯一拥有播放队列、当前媒体、播放意图和调度；设计系统不改变业务状态归属。
